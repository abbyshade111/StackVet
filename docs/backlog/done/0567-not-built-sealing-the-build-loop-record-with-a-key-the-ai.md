# Not built: sealing the build-loop record with a key the AI tool cannot reach

**Status:** done, 14 October 2026

From the loop-test session's observability ideas, 14 October 2026; the orchestrating session's assessment, agreed by
the owner: a done note, not a build.

**Why not.** The MCP server writes that record on every call, and the tool is what starts the server, so any key the
server can use, the tool can use; a passphrase would need the person at the keyboard for every call. The report's
honest sentence (a change before sealing is not caught; compare the chain's tip with an earlier report's) is the right
answer, and the hook-log proposal is the real fix for the same worry. Recorded here so the idea is not raised again
without this reason.
