# ADR-089: The part 4 audit's one-sample credits are checked in part, as the owner approved on 11 October 2026

**Status:** accepted, 11 October 2026, at the owner's word ("I agree and approve all your recommendations"), in the pull
request that makes the marks (backlog 0006, part 4).

## Context

Backlog 0006, part 4 asked for every running check that credits a requirement from one sample to be read against the
groups A to H of ADR-053, and marked "checked in part" where one sample cannot speak for the rest. The audit read the plain
credit sites across the check code. Its recommendations, approved on 11 October 2026, are applied here.

## Decision

1. **Group B** (one page, one sign-in, one session): the same email on two accounts (`oidc.rs`), the idle timeout and the
   lifetime of a session (`sessions.rs`), and the brute-force limit on one account (`signin.rs`).
2. **Group C** (one request or flow): the issuer, nonce, audience, signature and cross-session checks of the OIDC sign-in
   (`oidc.rs`); the expiry of the app's own token (`tokens.rs`); TRACE (`probes.rs`); the three GraphQL checks
   (`probes.rs`); the one request to the root answered 301 (`production.rs`); and the app stopping during the questions
   (`running.rs`).
3. **Group G** (one of several named operations): the context-word password (`passwords.rs`), and the email code used in
   another session and the guessing of email codes (`codes.rs`).
4. **Group H** (listed pages or forms): the password fields not masked (`passwords.rs`), and the sign-out control on each
   listed private page (`browser.rs`).
5. **Decisions approved as recommended:**
   - Password rule probes (length, composition, altered comparison, the current password on a change) are in part: one
     password is one sample of every password the rule governs.
   - A fixed list of names (`/.git` in `probes.rs`, the 16 private file names in `running.rs`) is in part, as a fixed list
     is not every file.
   - Per-client grants (V10.4.4, `running.rs`) are in part: a published server-wide list does not show per-client grants.
   - Other users' data on one record (`admin.rs`) is in part: one record of one owner is one sample.
6. **Kept whole, as recommended:** the long password (V6.2.9 says the length is "permitted", a capability), the
   port-level answer on port 80 (`production.rs`), the certificate and stapling checks (one certificate and one handshake
   per service, normally a server setting), and the answers a person or the AI records (`confirm.rs`, `notes.rs`,
   `design.rs`, `hand.rs`), whose tier already says whose answer it is.

## Not decided here

- The `running.rs` check of the admin page found by its address (`ADMIN_BY_ADDRESS`) was in the audit but not in the
  approved recommendations, so it is unchanged and is for the owner to decide.
- `suite.rs` and the `.gitignore` check in `config.rs` have not been read test by test, so they are unchanged.

## Consequences

- The reports of apps with a single listed item, page or action now say "checked in part" for those checks, as a single listed
  admin page already did. Nothing a correct app earned is taken away: an in-part credit still counts as evidence, and is
  shown as such.
- Each marked check's own test now asserts "in part", and a test fails when its mark is removed.
