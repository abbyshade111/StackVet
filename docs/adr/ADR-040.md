# ADR-040: A credential name over a sentence is reported low, and says so

**Status:** accepted. Decided by the owner on 4 October 2026, after family-hub's `WRONG_PASSWORD = "Your current
password isn't right."` was rated high (#597; DESIGN, "A credential name over a sentence is reported low, and says
so"). Recorded on 6 October 2026, after the second weekly review of the decision records found it had none.

**Governs:** `crates/sv-check/src/secrets.rs`, `crates/sv-check/src/secrets/tests.rs`. A pull request that changes it changes this record too, or says in its
description why it does not (`docs/adr/README.md`).

## Context

`secrets.credential-assignment` reports a name that says "credential" (`password`, `secret`, `token`) given a quoted
value that is not a placeholder and varies enough. A message shown to a person, under a name like `WRONG_PASSWORD`,
passes that test, and was reported high with the advice to change the credential. Dropping such values would also drop
a real passphrase that happens to be a sentence.

## Decision

- **Such a value is still reported,** at `low` severity and low confidence ("possible"), and says it reads like a
  sentence: a message is a false alarm to record with `sv review`, a passphrase is moved out of the code and changed.
- **"Reads like a sentence" is kept narrow,** because it lowers a finding: three or more ordinary words, one space
  apart, ending in `.`, `?`, or `!`. A digit or symbol in a word, mixed case inside a word, two spaces, or no closing
  mark, and it is not a sentence, and keeps `high`.
- **Redaction is unchanged.** The value is never shown, sentence or not: a passphrase that is a sentence is still a
  passphrase.
- **A low finding still counts.** It still makes its requirements need attention and still stops the scan's clean
  claim; setting it aside is the way to clear it.

## Considered

- **Not reporting a value that reads like a sentence.** Set aside by the owner: it would hide a passphrase.
- **Two-word messages (`Wrong password.`).** Kept high: too short to tell from a two-word passphrase.

## Consequences

- A merged finding keeps `sv`'s words over an outside tool's at the same severity, so this note is not lost when
  Bandit reports the same line (DESIGN, "The merge keeps `sv`'s words").
- Widening what reads like a sentence lowers more findings, and is a change to this record.

## Later, 6 October 2026: a review of this record, at the owner's asking

Read against the code the same day; the decision and how it is held are as written. One rule is narrower in the
record than in the code: a word may hold an apostrophe or a hyphen between letters (`isn't`, `sign-in`), and any word
but the last may end with a comma, and it is still a sentence (`crates/sv-check/src/secrets.rs`). Any other digit or
symbol in a word makes it not a sentence.

## Later, 12 October 2026 (the third weekly review)

Its three tests are in `crates/sv-check/src/secrets/tests.rs` now (moved on 8 October, #1058), not in `secrets.rs`. The behavior is as written.

## Later, 14 October 2026: the assignment finding no longer cites V13.2.3 (backlog 0431)

`secrets.credential-assignment` cited V13.3.1, SBD-AC-05, and V13.2.3, which asks that a credential used for service
authentication not be a default one (root/root, admin/admin). The rule passes over a value that reads as a word or has
little entropy, which is every stock default, so what it finds is never a default credential: it was raised for
`api_key = "sk-…"` and never for `password = "admin"`, and each finding marked V13.2.3 *needs attention* for a
requirement it had not found failing. It now cites V13.3.1 and SBD-AC-05 only, and V13.2.3 has no check. A rule that
looks for stock defaults would be the way to check it.

## Later, 15 October 2026: invite, access, and join codes are credentials, judged by their length (backlog 0531)

In the three-tool trial of 14 October 2026 a family app kept `INVITE_FOR_STACKVET = "stackvet-test-invite"` in its own
code, and no finding named it. The assignment rule now also reads a name whose words say it is a code people are given
to get in: `invite`, or `access` or `join` with `code` (`is_code_name` in `crates/sv-check/src/secrets.rs`), whole words
only, so `ERROR_CODE` and `COUNTRY_CODE` are not read. Such a code is made to be remembered and typed, never random,
so it is judged by its length (six characters or more, `MIN_CODE_CHARS`) rather than the 3.5 entropy every other
credential must reach; the trial's value reads 3.1. Placeholders, paths, URLs, and references are left out as for any
credential, and a sentence is still low under this record. It is reported at **medium**, below a key a program uses:
it opens one app's sign-up, and is often a fixture a seed script inserts; the fix says to make it when needed, or to
move a seed-only value into the test setup. The item asked for low when only a seed script uses the value; the check
reads one file at a time and cannot see that, so it is medium wherever it is. The citation is unchanged (V13.3.1,
SBD-AC-05); a code shorter than six characters is passed over, so no stock default is cited as V13.2.3 either.
