# ADR-109: The second loop trial tests `sv`'s waiting features on two briefs, with an outside check the builder never sees

**Status:** accepted, 12 October 2026, in the pull request that writes the trial's protocol and its tools (see "Later,
12 October 2026" below, which says where the build differs from this plan). Proposed the same day with the claim of
backlog 0257 (the loop trial) and 0006 part 21 (the outside tool). The owner's choices the same day, after the drafts trial's group A gave no reading for any draft
(`docs/prompts/drafts-trial/results.md`): "both briefs, $50 budget, scripted review is fine if labeled", and that the
outside-tool check and the observability features be used.

**Governs:** `tools/prompt_trial.py` (how each build is checked), `docs/prompts/loop-pilot/loop_trial.py` (how each
build is made), `docs/prompts/loop-pilot/loop_measures.py` and `docs/prompts/loop-2/score_loop2.py` (what is counted),
`docs/prompts/loop-2/scripted_review.py` (the script standing in for the owner), and `docs/prompts/loop-2/run_loop2.sh`
(what is run, in which order). A pull request that changes what a
trial runs, checks, or counts changes this record too, or says why not.

## Context

The loop trials so far asked whether a prompt prevents a mistake. The drafts trial of 12 October 2026 showed that the 5.5
models, given the club brief, already avoid what seven drafts warn about, so its controls bought no verdict. Meanwhile
about a dozen of `sv`'s own features have only been run against the scripted app: the account changes of backlog 0232
group G (ADR-105) and their `not-offered` list, the preflight's "`sv run` will look for this" hints (ADR-035, Later), how
each finding went away (design entry 0337), the typed-text check on every form (ADR-097), asking for several private
pages, and the spec sentences of 0044, 0198, and 0204. The observability features of 0226 to 0234 (the build-loop record,
ADR-084; what `sv` saw of the running app, ADR-082; history, ADR-083; `sv`'s own log, ADR-100) have the same gap. And
0006 part 21, an outside tool as an independent check of the loop arm, was folded into this trial by the owner on
9 October 2026.

Read against the code on 12 October 2026: the outside check is mostly built. `sv report --tools` runs Semgrep, Bandit,
and CodeQL, and `--keep-tool-output` keeps each one's own report (ADR-082, part 4); Semgrep and Bandit are installed on
the trial's Mac. The trials never asked for it: `tools/prompt_trial.py` runs `sv report --run` without `--tools`, and
every report of the drafts trial says so. The MCP server never runs an outside tool (`crates/sv-cli/src/mcp/mod.rs`), so
a builder in the loop arm never sees one.

## Decision

1. **The trial measures `sv`, not prompts.** For each waiting feature: whether it ran on a real AI-built app, whether
   it gave an answer or "not assessed" (and why, read from the evidence `sv` kept), and whether an answer was a false
   alarm, checked by hand on the evidence.
2. **Two briefs, both with `sv` attached through its MCP server (the loop arm).**
   - **The club brief, corrected:** it names `stackvet.toml` (it still said `securevibe.toml`), lists the text forms
     and the private pages for `sv` to ask, and lets the builder use git, signing its commits as an AI tool, so the
     note of AI commits made outside a merge (ADR-092) has something real to find.
   - **A new accounts brief:** sign-up, a password reset, and changes to the email, phone number, two-factor sign-in,
     and recovery address while signed in, each with a private page that shows the value, so ADR-105's checks and
     V6.3.8 can run. A second form of it offers none of the four changes and expects `not-offered`.
3. **The outside check.** After each build, `sv` checks it a second time with `--tools --keep-tool-output`, the builder
   never seeing the result, and each outside tool's findings are counted per arm. A loop arm that comes out cleaner on
   `sv`'s own checks and no cleaner on the outside tools' is the sign of a builder satisfying `sv` rather than making the
   app safer. Semgrep's rules are for non-commercial use, which a research trial is; the results say so.
4. **A scripted `sv review`, labeled.** The `not-offered` list is confirmed in `sv review` by a script standing in for
   the owner, with a key made for the trial. Every result that rests on it says "confirmed by a script standing in for
   the owner, not by a person". It is never used outside the trial.
5. **The observability features are used and tested.** `SV_LOG` is set for every check; `sv` is run twice on each build
   (once partway, once at the end), so the history explains a real difference; the build-loop record and the kept
   evidence are read for every build; and a crash file, if any, is a finding about `sv`.
6. **Money and models.** A budget of $50 of the owner's API credit, estimated in the protocol before any build. Nothing
   is canceled for cost (the owner, 12 October 2026); each build is capped at $5 against a runaway. Models by exact id:
   `claude-haiku-5-5` (never Haiku 4.5) and `claude-sonnet-5-5`. Controls first, as in the drafts trial, wherever a
   comparison is made.

## Consequences

- The trial's results speak to `sv`'s features on real apps, which no amount of the scripted app can.
- A second check per build adds a few minutes and no model money.
- The scripted review shows that the mechanism works on real apps; it says nothing about how an owner would answer.
- What any later trial runs, checks, or counts is a decision held by this record.

## Later, 12 October 2026: built, and where the build differs from the plan

The protocol is `docs/prompts/loop-2/protocol.md`, with its briefs, run script, scorer, and the scripted review beside
it. Where it differs from the decision above:

- **The club brief's arm without `sv` is not built again.** The drafts trial's twenty control builds of the same day
  are that arm, checked again with the outside tools; they differ from the new club builds only in the brief's
  corrections, which the results say beside every comparison. This saves about $6 of the $50.
- **The history is tested across each build's two checks**, the `--run` check and the outside tools' check, rather than
  a check partway through the build and one at the end: a copy of a build partway through does not exist without
  stopping the builder. History is switched on in the trial's own settings folder, and `sv compare` is run on each
  build's two reports.
- **Draft 17's own builds are not run by this protocol.** The accounts brief's builds without `sv` are its control; if
  they show its problem, the owner is asked first, with the cost.
- **A fault found in the measures while writing them:** `loop_measures.py` counted `sv`'s tools only under their old
  names (the server as `securevibe`, each tool as `securevibe_*`), while the server has answered as `stackvet_*` since the rename, so a new
  build in the loop arm would have shown no checks at all. It now reads both, held by a self-test that fails when
  either name is dropped, and the server is attached as `stackvet`.
- **The scripted review was tried before the protocol** on a drafts-trial build that had listed `not-offered` itself:
  it confirmed the list, left the app's level unconfirmed, and `sv` sealed the entry with the trial's own key.

## Later, 12 October 2026: the trials' script tests leave the Windows build

`crates/sv-check/tests/loop_measures.rs`, which runs the trials' scripts with `--self-test`, is compiled everywhere
but Windows (`#![cfg(not(windows))]`), at the owner's word that evening: the scripts are the trials' own tools, run
on Mac and Linux and not part of `sv`, and the second trial's scorer (`docs/prompts/loop-2/score_loop2.py`) had failed
its self-test on every Windows run of `main` since it landed (#1584) while passing on both, hiding any Windows
failure of `sv` under the same red mark. The coordination board's test left the Windows build the same way (ADR-061,
Later). Linux and Mac CI still run all of it; why the scorer fails on Windows is left to the trials' session.

## Later, 13 October 2026: the trial ran, and its tools were mended by what it found

The trial's results are `docs/prompts/loop-2/results.md`. Three amendments to the protocol, each said there: the run
script passed the scripted review's setting unquoted, and the path's space split it, so phase C's checks ran apart
(the run script now passes it whole); the build-loop record's measure is held to the calls made after the settings file
was written, since the record starts there; and two readings were added after phases A and B were seen, the `start`
command's settings and requirement ids written with underscores in tests' names (`docs/prompts/loop-pilot/loop_dodging.py`).
What the trial found about `sv` itself is in backlog items 0383 to 0389, each to be decided on its own.
