# ADR-126: A member's own page is saved through a `creates` entry and fetched where it is served

**Status:** accepted, 16 October 2026, in the pull request that builds it (backlog 0535). The proposal is the reviewing
subagent's, from the three-tool prompt trial of 14 October 2026 (backlog 0502), assigned to session honesty on the
coordination board. The owner chose this way of declaring the page on 16 October 2026, from three put to them: a
`creates` entry marked `page = true` (this record), a table of its own for pages, or leaving the pasted page a hand
check. Written by session honesty.

**Governs:** `crates/sv-check/src/signed_in/saved_page.rs`, the page field of
`crates/sv-manifest/src/lib.rs::CreateTemplate`, and its lines in `crates/sv-manifest/src/spec.rs`. A pull request that
changes what this check saves, fetches, credits, or cites, changes this record too, or says in its description why it
does not (`docs/adr/README.md`).

## Context

V3.2.1 asks that browsers are kept from rendering content in the wrong context, such as a user-uploaded file requested
directly; its controls include the `sandbox` directive of the Content-Security-Policy header and the `attachment`
disposition. An uploaded page is already fetched back and judged that way (`probe.uploaded-file-rendered`). A page a
member writes and the app serves on its own, such as a game or a pasted page, was not: in the trial, one app served
such pages from its own origin with inline scripts allowed, and another served them with `sandbox allow-scripts`.
Nothing read from the code told the two apart. `rich-text = true` says only that the app takes rich text, not where a
member's page is served.

## Decision

- **A `creates` entry may say `page = true`.** ADR-087's `read` already names where a record is served, so no new table
  is needed.
- **What is sent.** The first user saves, through that entry, a page holding a marked line of text and a marked script.
  It is read back at `read` (with `{id}`), or at the `Location` the save answered with.
- **How it is judged.** The answer must be a success holding the marked text; anything else (a refusal, a crash, a page
  without it) is said as not assessed (ADR-021). Then, as an uploaded page is judged:
  - Served as an attachment, with a `sandbox` policy, or with a type that is not a page: V3.2.1 is credited in part.
    The credit covers one page at the one address `read` names; anywhere else the app shows it was not tried.
  - Served as a page of this app, with the script as it was saved: a high finding, `probe.saved-page-rendered`.
  - Served as a page with the script taken out or escaped: neither. No script ran, so whether one would run is not
    seen; escaping is judged by the output-encoding checks.
- **A `read` on a host of its own is not fetched, and not credited.** The proposal would have counted such an address
  as another origin. But the run reaches only the app, and stackvet.toml names no address for the app in production, so
  the run cannot tell another origin from the app's own public name. Such an entry is said as not assessed, with the
  hand check to make. Crediting it on the manifest's word alone would be crediting a claim.

## Consequences

- The page half of backlog 0535 has a check; the upload half was already there.
- Held by `crates/sv-check/src/signed_in/saved_page_tests.rs` and two scenarios of the crash guard in
  `crates/sv-check/src/signed_in/mod.rs`.
