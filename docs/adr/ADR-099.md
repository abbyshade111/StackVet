# ADR-099: The owner can leave a folder out of the checks, with a reason the report prints, and keys are still looked for there

**Status:** accepted, 12 October 2026, in the pull request that builds it. Proposed the same day in the claim of
backlog 0249. The owner's word the same day, asked whether a folder left out should still be checked for real keys:
"yes"; and, of the same confirmation for group G, that the owner confirm it in `sv review`. Built as proposed; what the
build settled is under "Built" below.

**Governs:** `crates/sv-manifest/src/lib.rs` (the setting), `crates/sv-cli/src/left_out.rs` (which entries count,
what they set aside, and what the report says), `crates/sv-cli/src/static_scan.rs` (where the findings are set
aside, for the check and report commands alike), and `crates/sv-cli/src/review.rs` (the owner's confirmation).
A pull request that changes what these say about a folder left out changes this record too, or says in its
description why it does not (`docs/adr/README.md`).

## Context

A real report of 11 October 2026 had most of its noise from the owner's own test folder (backlog 0248). ADR-091 made
four Bandit rules in test code information rather than findings. The owner asked for more: a way to leave a whole
folder out, with the reason said in the report.

Two things already set folders apart. `[repository] not-the-app` (ADR-031) names folders that are not the app: their
code is still checked and their findings still count, listed apart, and they cannot switch a requirement on or off.
Folders that are an ecosystem's output (`dist/` beside a `package.json`) are skipped by every check and named in the
report. Neither lets the owner say "do not grade this folder, and here is why".

stackvet.toml is written by the AI coding tool. A setting that takes findings out of the count is the easiest place
for a tool to make a report look better than the app is.

## Decision

- **The setting.** `[[left-out]]` entries in stackvet.toml, each with `folder` and `why`, both required:
  `[[left-out]] folder = "tests/fixtures"`, `why = "recorded answers from the payment provider, not code we run"`.
  An entry without a reason is refused with a plain message.
- **What is left out.** Every check except the secrets scan leaves the folder's files out: no findings from them, and
  nothing in them is evidence of what the app uses, so they cannot switch a requirement on or off.
- **Keys are still looked for.** The secrets scan reads a folder left out as it reads any other, and a key found
  there is a finding, counted, with the folder named. The owner's word: an exposed key is serious enough to report
  wherever it sits.
- **Never silent.** The report lists each folder left out, its reason, how many files it holds, and whether the owner
  confirmed it, in "What was not examined".
- **The owner confirms it in `sv review`.** An entry counts only once a person has confirmed it in `sv review`, which
  seals it as `[design]` answers and the scope are sealed. Until then the folder is read as if it were in
  `not-the-app`: checked, its findings shown apart and counted, and the report says the entry waits for the owner's
  confirmation. So a tool that writes the entry cannot take findings out of the count by itself.
- **The same guards as `not-the-app` (ADR-031).** A list that would leave out every code file the app has is not used,
  and an entry holding the file the start command runs is refused, each said in the report.

## Consequences

- The owner can take a noisy folder out of the grade, and a reader sees which folder, why, and who said so.
- A real key is reported wherever it sits.
- A folder left out by mistake hides that folder's findings. The reason and the owner's confirmation in the report are
  the only guard; `sv` cannot know whether a folder is really not the app.

## Built, 12 October 2026

- **Where it is decided.** `Manifest::left_out` refuses an entry as `Manifest::not_the_app` refuses one (the check is
  now one function both use) and for an empty reason. `Manifest::set_apart` is `not-the-app`'s folders and every usable
  `[[left-out]]` folder, confirmed or not, and every command's scan reads the app through it, so ADR-031's guard (a
  list that would set apart all the code is not used) covers both kinds together.
- **Found, then set aside.** The checks still run on the whole app; `static_scan::settle`, which `sv check` and
  `sv report` share, moves each finding in a confirmed folder out of the count after the reviews are applied, unless
  it holds a key or password (`Finding::secret`), whichever tool found it. So the outside tools' findings there are
  set aside too, and the count of what was set aside is real.
- **The owner's confirmation** is a seal over the folder as written, the reason, `by`, and `on`
  (`sv_check::seal::left_out_fields`); it counts only with `by = "owner"`. `sv review` offers each usable entry not yet
  confirmed, refuses a reason under 40 characters (the bar for setting a finding aside), and asks for `owner`.
  Changing the folder or the reason afterward breaks the seal, and the folder is checked again.
- **What the report says:** one line per entry under "What was not examined", with its reason, who confirmed it,
  how many files it holds, and how many findings were set aside; or that it waits for `sv review`; or that it was not
  used. `sv check` prints the same lines.
- **Not in this build.** `sv audit` reads the folders as `not-the-app`: their packages are listed apart and still
  counted, confirmed or not.


**15 October 2026: a Python virtual environment under any name is left out by `sv`, and named (backlog 0595).** A
folder holding `pyvenv.cfg` (the file `python -m venv` writes; the file itself, not a link to one) is left out of
every check, as `venv/` and `.venv/` already were, and the report lists it among the folders left out as installed or
built code, saying that is normal. In the trial of 15 October 2026 the app's `env/` was walked as its own code and
its four `env/bin/python*` links made three check families "partly" without naming them. This changes what `sv`
reads: a folder of the app's own code that happens to hold a `pyvenv.cfg` is left out too, and the report names it
so the owner can move it. The "partly" line for links not followed now names the first three.
