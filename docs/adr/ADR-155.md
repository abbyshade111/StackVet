# ADR-155: A check that only reports a finding needs no record of its own

**Status:** accepted, 26 October 2026, at the owner's word (backlog 0674, from the fifth weekly review of the records).

**Governs:** the sentence on findings-only checks under "What needs one" in `docs/adr/README.md`. A pull request that
changes when a check needs a record of its own changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

A record is owed for a change to what counts as evidence or at which tier, to what `sv` runs or connects to, to what it
writes into somebody's folder, to the network fence, a dependency, a default that changes what a report concludes, and
every choice the owner makes when asked (`docs/adr/README.md`, "What needs one"). The checks added before 24 October
that only report a finding each had a record (ADR-065 to ADR-075, ADR-112, ADR-123), but most of those send requests
to a running app, or credit a requirement in part, and so changed what `sv` sends or what counts.

From 24 October, backlog 0625's plan said its findings-only checks needed "no decision record", and six merged on that
word: #2321 (stock default credentials), #2323 (LaTeX started with shell escape), #2344 (a key exchange with parameters
no longer safe), #2345 (a one-time code checked against a time the request sent), #2346 (email used as a way of signing
in), and #2347 (DOM clobbering). #2321 added the `findings-only` flag to `data/secret-rules.json` and
`tools/coverage.py`. Eight of the eleven pull requests that taught the code rules Rust (backlog 0661: #2286, #2288,
#2291, #2298, #2301, #2304, #2309, #2312), and #2311 (FastAPI's CORS setting, sqlx's queries, Gin's redirect), said the
same. The fifth weekly review (backlog 0674) asked whether a plan in a backlog item stands for the record, when the rules
say to look in `docs/adr/`. Asked, with a recommendation, the owner chose "One short ADR (Recommended)".

## Decision

- **A check that only reports a finding needs no record of its own.** That is a check which reads what is already read
  (the app's files, its `stackvet.toml`, what the run already saw), reports a finding with what to do, and credits
  nothing, not even in part. It does not change what counts as evidence: a requirement is credited only by a check that
  shows it met, and a finding can always be set aside, with a reason, in `sv review` (ADR-023). The family it joins
  keeps the count of its members: ADR-018's Later entries for the code rules, as on 26 October 2026.
- **It still needs one** when it also does any of what "What needs one" lists: credits a requirement, wholly or in part;
  sends a request or starts anything; reads a kind of file, a language, or a place it did not read before (Rust in the
  code rules has ADR-138, ADR-142, and ADR-145); changes a default, a severity bar, or what fails a run (`--fail-on`); or
  rests on a choice the owner made when asked.
- **Its citations are still claims.** A findings-only check cites only requirements it really speaks to, after reading
  their text (CLAUDE.md), and `tools/coverage.py` marks it `findings-only`, so `docs/COVERAGE.md` never counts it as able
  to credit.
- **What relied on the plan stands.** The six 0625 checks and the Rust and #2311 rule changes above fit the first rule;
  nothing in them is undone or recorded again.

## Alternatives considered

- **A record for each check,** as ADR-065 to ADR-075 had: eight or more records after the fact, each saying "reports a
  finding, credits nothing". The owner chose the policy over the paperwork.
- **The backlog plan stands,** with nothing in `docs/adr/`: the reasons would stay where the rules do not say to look.

## Consequences

- A findings-only check is one pull request with no record, and its family's count is brought up to date when a review
  notices.
- A check that starts as findings-only and later credits a requirement needs a record then, in the pull request that
  makes it credit.
- Small choices the review listed as unrecorded and cheap to undo stay as they are: #2346 reads only the owner's
  declared `email-code`, #2238 reads `{seed:NAME}` as a blank, and #2251 uses `docker exec rm -f --` in place of
  `sh -c`.
