# ADR-107: The StackVet mark in the heading of `report.html` and the dashboard, drawn in the page, with the pages' policy unchanged

**Status:** accepted, 12 October 2026, in the pull request that builds it; proposed the same day with the backlog claim
(0219 part 5). The owner's yes of 9 October 2026 to the mark in `report.html` and the dashboard, as an inline SVG so a
report opens no network connection, and again on 12 October ("the logo in the report and dashboard is cosmetic, but I
would like it done"). The same day, asked whether the browser-tab icon should come too, the owner chose the heading
alone: "I agree with your recommendation".

**Governs:** `crates/sv-report/src/html.rs::MARK` (the mark and its colors) and `crates/sv-report/src/mark_tests.rs`
(the mark held to the brand files). A pull request that changes these changes this record too, or says in its
description why it does not (`docs/adr/README.md`).

## Context

`sv` writes `report.html` into the app's folder, and `sv dashboard` writes a page of every app's last report. Both
carry a Content-Security-Policy in the page (`CSP_META`, "default-src 'none'"), since a report is a file someone hands
on and opens from disk, with no server to send a header: nothing loads, and no script runs. The StackVet logo, chosen
on 8 October (ADR-063), is in `docs/brand/`.

## Decision

The bracket mark of `docs/brand/stackvet-mark.svg` is drawn at the start of each page's first heading, as an SVG inside
the page. It fetches nothing, so the policy is unchanged. Its colors are rules in the pages' own style, so a page in a
dark theme shows the colors of `docs/brand/stackvet-mark-dark.svg`. It is marked as decoration (`aria-hidden`), since
the heading's words already name the page. The markdown reports carry no image.

`crates/sv-report/src/mark_tests.rs` holds the mark's paths and both themes' colors to the two brand files, so a
changed logo cannot leave an old one in the reports, and holds each page to the mark once in its heading, no image or
link loaded, and the policy as it was.

## Alternatives considered

- **The mark as the browser tab's icon too**, as a `data:` image in a `<link rel="icon">`: the policy refuses every
  image source, `data:` among them, so it would need `img-src data:` added. A `data:` image cannot run code or reach the
  network, and what a report prints is escaped, but it would be a loosening of the protection on a page `sv` writes
  into someone's folder, for something cosmetic. The owner chose the heading alone.
- **An `<img>` pointing at the brand file**: a report is handed on without the repository, and the policy refuses it.

## Consequences

- Each page carries about 500 bytes more.
- The browser tab shows the browser's default icon, as before.
- **Broken on purpose, each put back:** a path of the mark changed (the shape test failed), a color changed (the color
  test failed), and the mark left out of the dashboard's heading (the pages test failed).
