# ADR-150: CodeQL's C/C++ suite reads an app's C and C++ code without building it, for integer overflows (V1.4.2)

**Status:** accepted, 24 October 2026, in the pull request that builds it. Proposed the same day with the claim for
backlog 0625's eighth part.

**Governs:** the C/C++ CodeQL adapter and its suite's measured queries (`data/adapters.json`,
`data/codeql-suites.json`), and its tests. A pull request that changes how the database is made, which suite runs,
or which queries cite what, changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

V1.4.2 (level 2) asks that integer overflows in an app's unmanaged code are prevented by sign, range, and input
checks. It applies only to apps with C or C++ code of their own (the `unmanaged-code` condition), and nothing in `sv`
spoke to it. CodeQL runs only when the owner turns it on (ADR-115), from the CodeQL bundle they install, which holds
GitHub's query packs for every language it reads, C and C++ among them; so running its C/C++ suite asks nothing new
of the network. C and C++ are compiled, and CodeQL usually makes its database by building the code: by default it
runs an autobuild that runs the app's own build scripts. Every outside tool `sv` runs on an app is first tried to
show it runs none of the app's code (ADR-032).

The owner approved, on 24 October 2026, fetching what part 8 needed ("I approve of fetching CodeQL's C/C++ pack,
that's fine"), and downloading the CodeQL 2.27.2 bundle onto this machine to try it. The trial, that day, with the
bundle's own CodeQL 2.27.2, on an app of one C file planted with a Makefile, a `configure` script, a `CMakeLists.txt`
with an `execute_process`, and a `build.sh`, each writing a mark when run:

- `codeql database create --language=c-cpp --build-mode=none` finished in seven seconds, built no program, and left
  no mark: no build ran.
- The same without `--build-mode=none` began "Running build command: autobuild.sh", the step that runs an app's
  build scripts; it failed only because the bundle's build tracer is an Intel program, so the flag, not luck, is what
  keeps the build from running.
- `codeql database analyze` with `codeql/cpp-queries:codeql-suites/cpp-security-extended.qls`, 98 queries, found the
  planted `malloc(count * size)` from untrusted input twice: `cpp/integer-multiplication-cast-to-long` and
  `cpp/uncontrolled-allocation-size`.

## Decision

- **A C/C++ CodeQL adapter,** turned on with the other CodeQL adapters (`opt_in` CodeQL, ADR-115), for apps with C or
  C++ code: the database made with `--build-mode=none`, so nothing of the app's is built or run, and the bundle's C/C++
  security-extended suite run over it, offline.
- **V1.4.2, found failing only:** the suite's integer-overflow queries (CWE-190 and CWE-191: multiplication results
  cast wider, overflow checks that cannot work, arithmetic on uncontrolled values, comparisons with a wider type,
  allocation sizes from untrusted input, and unsigned differences compared with zero) are each a finding against
  V1.4.2; finding none credits nothing, since a database made without a build reads the code less fully than a built
  one, and an overflow can be in code the queries do not follow.
- **No new connection:** the bundle the owner installs already holds the C/C++ queries; `sv` fetches nothing.

## Alternatives considered

- **Build the code, for a fuller database.** Rejected: building runs the app's own scripts, which `sv` never does.
- **Cite V1.4.1 (buffer overflows) and V1.4.3 (use after free) too,** which other queries in the suite speak to. Left
  for a part of its own: each needs its own queries' texts read against the requirement.

## Consequences

- An owner who turns CodeQL on, with C or C++ in the app, is told of integer overflows its queries find.
- The suite's queries are measured into `data/codeql-suites.json` by `tools/codeql_suites.py`, as the others' are.

## Where the build differs

Built 24 October 2026. The adapter is `codeql-cpp`, for apps whose code is C or C++, and its seven rules each cite
V1.4.2 as found failing only: `cpp/integer-multiplication-cast-to-long`, `cpp/bad-addition-overflow-check`,
`cpp/signed-overflow-check`, `cpp/uncontrolled-arithmetic`, `cpp/comparison-with-wider-type`,
`cpp/uncontrolled-allocation-size`, and `cpp/unsigned-difference-expression-compared-zero`. The suite's 98 queries
are measured into the suites file as the other languages' are. Run end to end through `sv report`, with CodeQL turned
on in the app's settings file, on a one-file C app with the planted `malloc(count * size)`: the C/C++ suite ran in 21
seconds, V1.4.2 read "needs attention" from the first query at line 8, and the second, on the same line, was folded
into it as also reported by, as two rules on one line are. V1.4.1 and V1.4.3 stay not verified.
