# ADR-154: `sv` checks a public GitHub or GitLab project from its address, read first and started only when asked

**Status:** accepted, 25 October 2026, in the last of the three pull requests that build it (backlog 0670); proposed
the same day with its claim.

**Governs:** the fourth exception to the network fence, drawn and listed in `docs/ARCHITECTURE.md` ("The fence"), and
the fetch (`crates/sv-cli/src/fetch.rs`, and its hook into sv report in `crates/sv-cli/src/main.rs`), its
dependency on the zip crate (`crates/sv-cli/Cargo.toml`), the report, and the start of a fetched project, each named
here by its path when the pull request that builds it makes it. A pull request that changes which addresses are fetched, how, what is kept, what the report says to
its reader, or when a fetched project is started, changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

`sv` checks a folder on the owner's own computer, an app they built. On 25 October 2026 the owner asked for "an option
to use StackVet to evaluate any public code repository - for example, supply a GitHub or GitLab link to the tool and
have it run all the tests so a user can decide if they want to accept the risk of using the code themselves" (backlog
0670). That reader is someone else: not the project's author, deciding whether to trust it.

It touches the two firmest lines `sv` keeps. Fetching code is a network connection, and `sv` opens none of its own
beyond three named exceptions (`sv probe`, the install step, and the outside tools' rule packs). Starting the project
runs code nobody has vetted. Asked the same day, with a recommendation for each, the owner chose:

- **Hosts:** "GitHub and GitLab only".
- **How:** "Download one snapshot".
- **Starting it:** "Only when asked, and only after running all static checks first".
- **The report:** "A reader weighing a risk".

## Decision

- **A fourth exception to the fence, asked for by name:** `sv report` given a project's address,
  `https://github.com/OWNER/REPO` or `https://gitlab.com/GROUP/PROJECT` (with a branch, tag, or commit where the
  address names one), downloads that host's own archive of one commit through `curl`, as `sv probe` uses it: HTTPS
  only, those two hosts and the download hosts they send to, a limit on redirects, on the size downloaded, and on time.
  Any other address is refused before anything is sent. Nothing is sent but the request for the archive: no
  credentials, no token, and nothing about the person's own folders.
- **Nothing in the download runs.** An archive holds files, not Git: no hooks, no filters, no submodules, and no large
  files. It is unpacked by `sv` itself into a folder it makes and names, refusing any entry that would land outside it
  or is a link, and stopping at a limit on the files and the size unpacked.
- **The commit is named.** The report says which commit it checked, read from the archive, since the project may
  change the next day, and the folder stays for the person to read or delete; `sv` says where it is.
- **Read first.** Every check that reads code runs as for any app: `sv`'s own rules, the keys and passwords, the
  packages and their known vulnerabilities when there is a database, and the outside tools. The checks that need the
  app running are said not assessed, with why.
- **Started only when asked, and only after.** With `--run`, and only once every static check has finished, a project
  that carries its own `stackvet.toml` saying how to start it is started in the fence as any app is (ADR-019). The
  report says, at its top, that code nobody vetted was run, in a fenced container with no way out. Without its own
  `stackvet.toml` there is nothing to start it with, and that is said.
- **A report for a reader weighing a risk.** The owner's questions in `stackvet.toml` cannot be answered by somebody
  else, so they stay unanswered and are read as nothing (ADR-015); the report names which requirements that leaves
  open. A finding is worded as a risk to weigh, not a task to do; the summary never reads "nothing found", or the
  project's own tests passing, as the project being safe; and the report names the project, its address, and the
  commit.
- **Built in three pull requests:** the fetch and unpacking, with the fence's picture and table changed; the report for
  this reader; then the start when asked.

## Alternatives considered

- **Any HTTPS Git address.** The owner chose GitHub and GitLab only; more can be added, each a change to this record.
- **A shallow `git clone`.** The owner chose the archive: no Git needed, and nothing in it can run.
- **Never starting a fetched project.** The owner chose to allow it when asked, after the static checks.
- **The owner's usual report, with a note.** The owner chose a report written for this reader.

## Consequences

- Someone deciding whether to use a public project can see what `sv` says about it, without the project's author.
- `sv` gains a network connection the person asks for by name, with the same kind of limits `sv probe` has; the
  fence's picture, its table, and CLAUDE.md's sentence about it say four exceptions.
- A report on someone else's project leaves more open than an owner's, and says why, rather than reading the open
  questions as passes.

## Later, 25 October 2026: the fetch (backlog 0670, part 1)

Built as decided, with these choices made in the building:

- **A dependency, the owner's choice.** To unpack an archive `sv` needs a reader for zip files. Asked the same day,
  with a recommendation, the owner chose "Add a Rust zip library (Recommended)": read in `sv`'s own code, where each
  entry is checked before it is written, the same on every platform. It is the `zip` crate, version
  9, with its default features off and only its pure Rust reader of compressed entries on (`deflate-flate2-zlib-rs`):
  no encryption, no other compression, and no code of any other language. `sv` reads with it and never writes an
  archive with it, outside its own tests.
- **The address.** `sv report` reads anything with `://` in it as an address, so a folder's name is never mistaken
  for one, and an address it cannot fetch is refused with what it expected, before anything is sent: only `https://`,
  only `github.com` and `gitlab.com`, a project's own address or its `/tree/BRANCH` or `/commit/SHA`, and names made
  of letters, digits, `.`, `_`, `-`, and `/`.
- **The download.** GitHub's `archive/` address, which sends to `codeload.github.com`, and GitLab's public API
  archive. `curl` runs with `--disable` (no `.curlrc`), `--proto =https`, and `--max-redirs 0`: each redirect is read
  by `sv`, checked against the three hosts, and refused before it is asked when it goes anywhere else, at most three.
  The limits are 500 MB and ten minutes for a request.
- **The unpacking.** Into a folder of `sv`'s own, `stackvet-fetched/HOST/PATH-COMMIT` under the folder it was
  started in, never over one already there (a second fetch of the same commit is numbered beside the first, which
  the person may have changed). Every file is written new, with no permission to run. An entry that is a link, whose
  name has a root, a drive, `..`, `\`, or `:`, or that has the name of a file already written, is left out and named
  in the terminal; 50,000 files and 2 GB unpacked, counted as read rather than as the archive claims, stop it. Its
  download and its half-made folder are removed when it fails.
- **The commit** is read from the archive: GitHub's carries it in the archive's comment, and GitLab's top folder
  ends with it. When neither says, the folder is named `commit-not-said` and the terminal says so.
- **A project that carries no `stackvet.toml`** gets one written by `sv` into that folder, of comments only, saying
  nobody answered its questions, so each stays unanswered and is read as nothing (ADR-015). One the project carries is
  left as it is; what the report makes of an author's answers is the second part's.
- **`--run` with an address is refused** until the third part, before anything is fetched.
- **What was tried.** Tests fetch nothing from the network: a stand-in answers for the host inside the module's own
  tests, and a stand-in `curl` (named by `SV_CURL_FOR_TEST`, a debug build's switch, as `sv probe`'s tests use it)
  answers as GitHub does for the tests through the `sv` binary.
- **Tried against both hosts, 25 October 2026, at the owner's word.** `https://github.com/octocat/Hello-World` came
  through `codeload.github.com` as its `master` commit, `7fd1a60b01f91b314f59955a4e4d4e80d8edf11d`, read from the
  archive; `https://gitlab.com/pages/plain-html` came from GitLab's API archive as
  `87e8c32b8918a836c09475e0f668ea7c436d3758`, which GitLab's API names as the newest commit on its default branch. Each
  report was written whole, exit status 0.

## Later, 25 October 2026: the report for a reader weighing a risk (backlog 0670, part 2)

Built as decided, with these choices made in the building:

- **How a report knows.** The fetch keeps a record beside the project's folder, `PROJECT-COMMIT.fetched.json` in
  `stackvet-fetched/HOST/OWNER/`, never inside it, where an archive could put one of its own: the address, the commit,
  whose answers the `stackvet.toml` holds, and that file's SHA-256 as fetched. Every report of the folder reads it,
  from `sv report` with the address or the folder, and from the MCP server, but only for a folder inside a
  `stackvet-fetched` folder, so an app of the person's own is never read as somebody else's. A `stackvet.toml` changed
  since the fetch is said to be: its answers are then whoever changed it, neither nobody's nor the author's.
- **Every page says whose it is at its top,** after the line saying which `sv` made it: report.html, compliance.md,
  security.md, low-findings.md, the four short pages, and before-going-live.md. That it is somebody else's project,
  its address and commit, that it may have changed since, that it was checked without running any of it; that where a
  page says to fix something it is a risk to weigh, fixing it being the author's to do; that nothing found is not the
  same as safe; and whose answers there are. The address is text, never a link, so the page still fetches nothing.
- **The short version counts risks to weigh,** not things to fix, and with nothing found says "That does not make it
  safe to use", then how many of the requirements that apply had nothing look at them, how many of those rest on what
  only the author could say, and how many could not be placed without the author's answers.
- **What to do next is the reader's:** weigh the risks found, know what is left open (none of it passed), and know
  the project was never started. None of the owner's steps: fixing, answering, writing tests, `sv review`, or `--run`.
- **Left as they are:** each finding's own words, and the short pages' titles ("Fix now" among them), which the
  banner above them tells the reader how to read. `report.json` carries the record as `fetched`.

## Later, 25 October 2026: started only when asked (backlog 0670, part 3)

Built as decided, with one choice of the owner's and these made in the building:

- **The install step, the owner's choice.** A fetched project's own `stackvet.toml` can say `install = true`, which
  would open the fence's second exception on its author's word. Asked the same day, with a recommendation, the owner
  chose "Only with --install (Recommended)": `sv report <address> --run --install`. Without `--install`, a project
  that asks for its packages is not started, and the report says why: every check of a running app needs it to start,
  and it cannot start without them. `--install` goes only with `--run`, and only for a fetched project; an app of the
  person's own says `install = true` in its own `stackvet.toml`, as before.
- **When.** The run is the report's ninth stage of ten, after every stage that reads the code, the outside tools
  among them; a test holds that order. The run itself is the one `sv run` and every `--run` make, in the fence
  (ADR-019).
- **Only when it says how.** A project that carried no `stackvet.toml` has one `sv` wrote, of comments only: nothing
  says how to start it, and `sv` does not guess. It is not started, and the report says so, as a run that could not
  start (exit status 2). Both refusals are asked in `sv_cli::probe_the_running_app` before the run's plan is made,
  through `fetch::why_not_start`, so no container backend is asked for either.
- **Said at the top.** When it was started, every page's first line says code nobody vetted was run, after every
  check that reads its code, in a container on a network with no way out, its folder read-only and every capability
  dropped; and the next steps no longer say it was never started.
- **What was tried.** The refusals through the `sv` binary with a stand-in `curl`, needing no container backend.
  Starting a fetched project for real is the run every app has, tested where `sv run` is; it was not tried here
  against a project fetched from GitHub or GitLab.

## Later, 26 October 2026: under the banner, the pages speak to the reader too (backlog 0676)

The first report on a project fetched from GitHub had the banner on every page, and under it three passages written
for an app's owner. Each now speaks to the reader of a fetched project; a report on an app of the person's own says
what it did before.

- **The level says whose answers it rests on.** With no `stackvet.toml` of the project's own, it says nobody has said
  who uses the project or what it holds about people, that those are the author's to give, and that the level is not
  a judgment of the project. With the author's, it calls them the author's word, which `sv` did not check; changed
  since the fetch, the word of whoever changed them. It never asks the reader to confirm them with `sv review`
  (`sv_report::bluf`).
- **A finding is a risk to weigh.** Its next step says to read the code it names and decide whether it matters for
  how the reader would use the project, and that fixing it is the author's to do, rather than to fix it or write a
  `[[finding-review]]` (`sv_report::next_step`, ADR-098's step for a fetched project).
- **No build history of a build the reader had no part in.** A record with no calls in it, or one turned off, is left
  out; a record the project brought with calls in it is said to be its author's tools', which `sv` cannot check.

Tested in `crates/sv-report/src/fetched/reader_words_tests.rs` across all nine pages, each guard broken on purpose and
seen red, and on a copy of the first fetched project, run again.

## Later, 26 October 2026: the rest of the report speaks to the reader (backlog 0677)

Backlog 0676 fixed three passages; reading the first fetched report again found the rest. Of a fetched project, each
of these now says what the reader can do, or that the work is the author's, and a report on an app of the person's
own says what it did before:

- **A requirement not verified** says a test of the project's own could settle it, which its author would write, not
  "ask your AI coding tool to write one" (`sv_report::could_settle`).
- **The requirements about building with AI** reached by `sv rules` say that is a rule `sv` gives an AI coding tool,
  which says nothing of how this project was built (`AiProcess::route_text`).
- **A question only a person can answer** says only the project's author can, and that it is left open until then,
  in the list of questions (`fetched::route_said`), among what was not examined (`fetched::gap_why`, which also leaves
  out "`sv questions` prints them for its chat"), and among the requirements nobody has placed.
- **An answer in the project's own `stackvet.toml`** is the author's, or whoever's changed it since the fetch, never
  "read as your AI coding tool's" (`ClaimLine::who_said_in`).
- **Each page's "For:" line** names the reader weighing the project, never their AI coding tool, and the checklist
  as the author's, or the reader's only if they put the project on the internet themselves (`folder::for_whom`).
- **The checklist** opens by saying so, and its parts no longer ask the reader to answer, fix, or tick in
  `sv review` (`checklist::opening`, `Part::about_in`).

The fetched record is now set as soon as the report is made (`put_together`), not after, so what is worked out from
the report afterward, such as what could settle each requirement, knows whose project it is. A test through the `sv`
binary, `crates/sv-cli/tests/fetched_reader_words.rs`, fetches a small project with a stand-in `curl`, reads every
page for the owner's words and finds the reader's in their place, and reports the same code as the person's own to
see the owner's words kept; each of the eleven guards was broken on purpose and seen red.

**Left as it is,** counted on the first fetched project, run again with this in: 17 mentions of "your AI coding
tool" on its pages, from about 250. They are the advice from `sv-check`'s git history check to ask an AI coding tool
to put the app in git (3); the ways to check by hand in `data/human-checks.json`, such as "Ask your AI coding tool to
show you ..." (6), which a reader can still do with a tool of their own; and sentences that explain the report
rather than ask anything of the reader: the status legend, the count of the AI-process requirements `sv rules`
reaches, where `sv mcp` gives the long list, and `information.md`'s line saying what it holds. The status names that
say an answer rests on "your AI coding tool's" word appear only when a fetched project carried a `stackvet.toml` of
its own.
