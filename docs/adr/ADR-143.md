# ADR-143: The coding rules carry a few lines for each framework the app's package lists name, each tied to the check that catches its fault

**Status:** accepted, 24 October 2026, in the pull request that builds backlog 0663. Proposed that day with the claim,
at the owner's word: "once the PR merges, please claim and start the first one", after a session read Wiz's
open-source rules files and filed what they suggest as backlog 0663 to 0665. Where the build differs from the plan is
under "As built", below.

**Governs:** the lines and how they are held (`data/stack-guidance.json`, `crates/sv-check/src/stack_guidance.rs`,
`crates/sv-check/tests/stack_guidance.rs`), where they are given (`crates/sv-cli/src/lib.rs::coding_rules_for`,
`crates/sv-cli/src/lib.rs::RulesForApp`, the frameworks field of the guidance tool's answer,
`crates/sv-cli/src/mcp/tools.rs::guidance` and `crates/sv-cli/src/mcp/catalog.rs::stackvet_guidance`), and the brief's pointer to them
(`crates/sv-cli/src/brief.rs::markdown_with`). A pull request that changes how a framework is recognized, which lines a
framework is given, what they are tied to, or where they are written, changes this record too, or says in its
description why it does not (`docs/adr/README.md`).

## Context

`sv`'s coding rules (`data/coding-rules.json`, ADR-017) are adapted from OWASP AISVS Appendix C and say how the AI
coding tool behaves: keep keys out of the chat, treat fetched text as data, never merge its own work. None says how to
write the code in a given framework, so the tool building a Flask app is never told that Jinja escapes for it until
`|safe` or `Markup` is used on a value from the request, which is exactly what `sv`'s check then finds.

Wiz's rules files (https://github.com/wiz-sec-public/secure-rules-files, commit `04101f88`) give a short list like this
for nine stacks. Their license, CC BY-NC-ND 4.0, forbids adapting the text, and their copies for one stack disagree
with each other (backlog 0664), so they are a prompt for what to consider, never a source.

`sv` already reads the package names an app declares (`sv_scan::deps::read_in`), which is how a condition such as
`jwt` is recognized (`data/tech-signatures.json`). It does not name the app's frameworks anywhere.

## Decision

- **A new data file, `data/stack-guidance.json`,** read through `sv_frameworks::data` (ADR-036), lists frameworks.
  Each names the packages that show it, by ecosystem, in the shape `data/tech-signatures.json` uses, and a few lines
  for it, each in this project's own words.
- **A framework is recognized only by a package the app declares.** A package list `sv` could not read leaves the
  frameworks it would have shown unknown, and the section says so rather than going quiet. No line is given for a
  framework that is not found, and none at all when none is.
- **Every line is tied to the check that catches its fault**: a code rule's id (`ast.…`), a configuration check's id,
  or an outside tool's rule that `sv` runs. `load` refuses a line that names an id `sv` does not have, and a line with
  no such check says so in the file, with why. A line carries the requirements its check already cites, so the
  citation is the one made when the check was written; a line that adds one does so only after reading its text, and
  `load` refuses a line that ends up citing none.
- **Where it goes:** after the coding rules, under a heading of its own, wherever they are written: the section `sv
  rules` writes into `AGENTS.md`, `stackvet_guidance`, and `sv brief`. The same lines, rendered from the one file, in
  every place (backlog 0664).
- **Credit:** the section's own line says the lines are StackVet's, and that the choice of topics was inspired by
  Wiz's files, named and linked, with none of their text. It is not covered by the CC BY-SA 4.0 credit of the AISVS
  rules, because it is not adapted from them.
- **What it is worth:** nothing, as evidence, like the coding rules. No requirement changes status because a line was
  given, and the report says nothing of it.

## Consequences

- An app whose framework `sv` recognizes is told, before it is built, the framework's safe way and the check that
  will look; an app whose framework is not listed is told nothing new, and the section says which frameworks are.
- A new framework, or a new line, is a data change, held by `load`'s checks and a test that renders every place the
  lines go.
- `sv` connects to nothing new and writes nothing new into the app's folder: the lines go inside the section between
  `sv`'s markers that it already writes.

## As built, 24 October 2026

- **No line without a check.** The plan let a line with no check say why; none was needed, so `load` refuses a
  line that names no check, and every line is held by its fault.
- **Every check a line names must find a fault**, not only one of them: `load` refuses a line naming a check with no
  fault for it, so a line cannot name a second check that never looks at the framework's code.
- **The test removed three lines before they shipped.** Each named a rule that does not read that framework's way of
  writing the fault: FastAPI's `CORSMiddleware` (the CORS rule reads only flask-cors in Python), sqlx's
  `sqlx::query(&format!(…))` (the Rust SQL rule reads method calls such as rusqlite's), and Gin's `c.Redirect(code,
  address)` (the Go redirect rule reads net/http's four-argument form). They are gaps in the rules, filed as backlog
  0666, and each line goes back when its rule reads it. One fault was wrong rather than the rule: tower-http refuses
  `Any` with credentials when the app starts, so Axum's line names `AllowOrigin::mirror_request()`, which the rule reads.
- **Advice a check does not cover says so in the line.** The CSRF rule finds protection switched off, not protection
  never added, so the Flask and Django lines say "`sv` does not check that it was added" (or "is still there").
- **A package list is named by its file name alone** ("named in package.json"), never its folder: the folders are
  named by whoever wrote the app, and the section goes into `AGENTS.md`, which the AI tool reads as orders (ADR-066,
  point 5). Held by `a_folder_name_from_the_app_never_reaches_the_section`, which failed with the whole path put back.
- **The brief points to the lines rather than giving them.** `sv brief` is built from the report, which does not carry
  the app's package lists, so it says in one sentence that `stackvet_guidance` (`sv rules`) gives them; reading the
  lists again inside the brief would be a second way to find the same frameworks.
- **The first frameworks:** Flask, Django, FastAPI, Express, React, Ruby on Rails, Axum, and Gin, 26 lines, each with
  its fault. Actix, Spring, Laravel, and the rest are a data change when someone writes lines for them.
- **Broken on purpose:** with `ast.html-from-value`'s Python function pattern changed to match nothing, the
  stack-guidance test failed on Flask's fault; with `load`'s rule that each named check needs a fault switched off,
  `a_line_naming_a_check_with_no_fault_for_it_is_refused` failed. Both passed once put back.

## Later, 26 October 2026 (the fifth weekly review)

The count of 26 lines is 29: Flask 4, Django 5, FastAPI 3, Express 4, React 2, Rails 5, Axum 3, Gin 3 (`data/stack-guidance.json`). The test had removed three lines before they shipped; backlog 0666 (24 October) put the FastAPI CORS, sqlx, and Gin redirect lines back with the rules that read them, as the record said each would be. No decision changes.
