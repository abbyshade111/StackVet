# ADR-118: Several flows and WebSocket paths in stackvet.toml, so the checks that try one can try each

**Status:** proposed, 14 October 2026, in the claim of backlog 0232, part 3 (group C). The owner's word the same day,
asked by session honesty: add list keys beside the single ones. Accepted, or changed, in the pull request that builds
it.

**Governs:** `crates/sv-manifest/src/lib.rs::FlowSection` (and the flows, websockets, and private-websockets keys
beside it), `crates/sv-check/src/signed_in/flows.rs::flow_checks`,
`crates/sv-check/src/signed_in/sessions.rs::websocket_session_checks`, and
`crates/sv-check/src/probes.rs::evaluate_api` (its WebSocket part). A pull request that changes what these do with
the lists changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

Three groups of credits rest on the one entry stackvet.toml has room for, and are *checked in part* for that alone
(ADR-053, Later; the one-sample inventory, group C):

- `probe.flow-step-skipped` (V2.3.1, steps of a business flow taken in order) tries the steps of the one `flow`.
- `probe.websocket-without-session` (V4.4.4) and the signed-in `probe.websocket-origin-unchecked` (V4.4.2) open the
  one `private-websocket`.
- The anonymous `probe.websocket-origin-unchecked` (V4.4.2) opens the one `websocket` under `[stack.run]`.

An app often has more than one flow (a checkout, a sign-up with steps, a password reset) and sometimes more than one
WebSocket, each perhaps handled by other code.

## Decision (proposed)

- **Lists beside the ones.** `flows = [ { steps = [...], completed = "..." }, ... ]` beside `flow`;
  `private-websockets = ["/ws", "/chat"]` beside `private-websocket`; and `websockets = [...]` beside `websocket`.
  The single keys keep working as one entry. Giving both the one and the list is refused with a plain message, as
  `text-form` and `text-forms` are (ADR-097).
- **Each one tried.** Each flow, and each WebSocket path, is tried as the one is now, with request ids that name it, so
  a crash at one is never read as another's refusal (ADR-021).
- **A finding names the one that failed.** One flow whose step could be skipped, or one socket that opens without a
  session or from another site, is a finding naming it; the credit names every one that held.
- **When a credit is whole.** Only when two or more were named, each could be judged (its own control worked: the
  flow finished in order, the socket opened signed in), and every one held. One named, or one that could not be
  judged, leaves the credit in part and says which.
- **Nothing else changes.** What each try sends, and what counts as held, are as now.

## Alternatives considered

- **Make `flow` and `websocket` themselves lists.** Shorter, but every stackvet.toml that names one would change
  meaning or fail to read; a key beside the old one keeps them working.
- **Leave them in part.** No format change, but an app with three flows that all hold would never be *checked* on
  V2.3.1.

## Consequences

- An app that names two or more flows, or two or more WebSocket paths, each holding, is *checked* on the requirements
  those credits speak to, not in part.
- stackvet.toml gains three optional keys; files without them read as before.
