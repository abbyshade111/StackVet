# ADR-101: `sv connect` prints the settings an AI coding tool needs and writes nothing, and one prompt sets StackVet up

**Status:** accepted, 12 October 2026, written by the third weekly review of the decision records, three days after the
build (#1264, 9 October). The decision is the owner's, of 9 October 2026 ("as recommended", backlog 0217 part 1); the
reasons are those of the design entry (`docs/design/0339-sv-connect-and-a-prompt-that-sets-stackvet-up-9-october-2026.md`).

**Governs:** `crates/sv-cli/src/connect.rs` and `docs/prompts/setup.md`. A pull request that changes these changes this
record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

Connecting an AI coding tool to StackVet meant a settings file with the app folder's full path typed in three places and
`docker`'s full path in a fourth. A wrong path fails silently: the tool simply has no `stackvet_` tools.

## Decision

- **`sv connect TOOL` prints the settings block** for Claude, VS Code or Cursor on standard output, and the name of the
  file it goes in on standard error. **It writes nothing**, so it adds nothing to what `sv` writes into someone's
  folder; the AI tool or the person writes the file.
- **With `--docker`, the block starts the container as the guide does:** `--network none`, the folder mounted at its own
  place, and with `--user` the user before the image. A bare `docker` is refused: an app started from the Dock often
  cannot find it. Inside the container `sv connect` stops and asks for `--docker`.
- **`docs/prompts/setup.md` is a prompt the person pastes into their AI tool.** It has the tool check Docker, pull the
  published image, run `git init`, find `docker`, run `sv connect` through the container, show the person the file before
  writing it, and stop on Windows. It asks before installing anything or changing anything outside the folder.
- **Evidence:** none. It reads no file of the app's and credits nothing.

## Alternatives considered

- **Have `sv connect` write the file.** It would be a new place `sv` writes into someone's folder (ADR-017).
- **Copy the settings text into the prompt.** It would drift from the guide.

## Consequences

- The prompt tells a person's AI tool to run Docker and write a config file. That is the person's tool acting on the
  person's say-so, shown the file first; `sv` does neither.
- Neither the command through the container nor the prompt has been tried in Claude Code, VS Code or Cursor from an
  empty folder, and the guide says so.

## Tested

`crates/sv-cli/src/connect/tests.rs` and `crates/sv-cli/tests/connect.rs`, the second running the real `sv` and holding the
prompt to the published image name, the container options, and the options `sv connect` takes.

## Later, 12 October 2026: one prompt becomes a library, and Windows has a route of its own

At the owner's asking, from the website's words (backlog 0224, 0370), `docs/prompts/setup.md` is a library for someone
who has used an AI chat but never built an app with one: four prompts copied one at a time (look at the computer and
change nothing; help install what is missing, with a yes before each install and only official pages, Docker Desktop
or Colima on a Mac or Linux; set StackVet up; check it is connected with `stackvet_status`). The Mac and Linux setup
prompt is the one this record describes, unchanged except that on Windows it now points at the Windows version
rather than stopping. **The Windows version** installs StackVet with Scoop and runs `stackvet connect TOOL` with no
`--docker`, because the Docker block cannot be made there: `--docker` takes only a path starting with `/`, and a
Windows folder cannot be mounted at its own place in a Linux container (the owner's choice: Scoop is the Windows route,
and Docker there waits, ADR-108, Later, and backlog 0375). It types `stackvet`, never `sv`, which PowerShell reads as
`Set-Variable`. Both versions stop and say so when the AI tool is not one `sv connect` has settings for. `sv connect`
itself is unchanged. `crates/sv-cli/tests/setup_prompts.rs` holds the library; broken on purpose before the push
(the Windows prompt typing `sv connect`, the first prompt told to fix things), it failed once each time.

## Later, 13 October 2026: prompt 2 makes the app's folder first

From the owner's first trial of the library, in Antigravity: prompt 1 ran in that tool's own scratch folder,
`~/.gemini/antigravity/scratch`, which the library had assumed the person would have replaced with a folder of their
own. At the owner's asking, prompt 1 now also says, still only looking, whether the folder looks made for an app or
like a scratch, temporary, or settings folder; and prompt 2 starts with the folder: when it is not an empty folder
made for the app, the AI tool offers to make `my-app` in the home folder, asks before making it, and says how to open
it in the tool, and waits, before anything is installed. Prompt 2 also says to start Docker when nothing is missing
but Docker is not running. The page above the prompts says the AI tool may ask to read github.com or
raw.githubusercontent.com, StackVet's own instructions that prompt 1 points it to, and that reading them is safe to
allow. `crates/sv-cli/tests/setup_prompts.rs` holds each.

## Later, 13 October 2026: no prompt names an app's buttons or menus

Also from the trial in Antigravity: told to open the folder, the AI tool gave a menu path that app does not have.
The owner's rule, the same day: the prompts say what has to happen, never which button or menu does it, since apps
differ and change over time, and the AI tool knows its own. So the folder step and the step that loads StackVet's
settings ask for the app's own words, and for the tool to say so and ask, rather than guess, when it is not sure; VS
Code's **Start** button and Docker Desktop's question about container kinds are gone from the prompts. What stays is
StackVet's own: the words `sv connect` takes (`claude`, `vscode`, `cursor`), the settings files it names, and the
terminal commands. `no_prompt_names_an_apps_buttons_or_menus` in `crates/sv-cli/tests/setup_prompts.rs` holds it.
Opening the folder started a new chat in Antigravity, so prompt 2 now says it may, and that the person then pastes
prompt 1 there and prompt 2 again, which skips what is done.
