# ADR-115: The report is also written as a PDF, by `sv` itself

**Status:** accepted, 14 October 2026, in the pull request that builds it (backlog 0412). The request is the owner's,
13 October 2026, after a report was sent as a zip: "at one point there was a pdf version of reports in the bundle, can
we start doing that again so there's a format people can easily read?" The owner agreed the same day that the PDF
holds `compliance.md`'s order with each finding written out in full, rather than the two files joined, which would
print their shared opening and "What was not examined" twice. The rest of the decision is the backlog item's proposal,
built as written.

**Governs:** `crates/sv-report/src/pdf.rs` and the files under it: `crates/sv-report/src/pdf/write.rs` (the writer),
`crates/sv-report/src/pdf/fonts.rs`, `crates/sv-report/src/pdf/layout.rs`, `crates/sv-report/src/pdf/read.rs`, and
`crates/sv-report/src/pdf/back.rs` (the reader the tests read it back with); `crates/sv-report/src/markdown.rs::pdf_text`,
the text it is laid out from; and the setting report-paper in `crates/sv-manifest/src/lib.rs::AppSection`. A pull request that changes what the PDF holds, how it
is written, or what it costs changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

SecureVibe v1 wrote a PDF beside each HTML report with a writer of its own (v1's ADR-013, 25 September 2026,
`0a59456`; the paper size as a setting, `ed75b52`). The writer was TypeScript, so it did not come across when `sv` was
written in Rust, and no `sv` report has had a PDF since. A report folder held eight files; only `report.html` was easy
for a person to read, and only in a browser. A person handing a report on, by email or in a zip, had nothing a
recipient could simply open and print.

## Decision

- **`sv report` writes `report.pdf`** into the report folder, the ninth of `crates/sv-cli/src/report_files.rs`, so it
  is sealed with the others, offered by the MCP server, and carried by `sv bundle`. It holds what a person reads, in
  `compliance.md`'s order: the short version, the findings written out in full as `security.md` writes them, what was
  set aside, how the report was made, what was not examined, the requirements by chapter, every low-severity finding
  in full, and the appendix. It is laid out from Markdown made by the same renderer as `compliance.md`
  (`markdown::pdf_text`), so the PDF cannot say something the other reports do not.
- **`sv` writes the file itself, with no new dependency.** A small writer over the five fonts every PDF reader has
  without being given them (Helvetica in four forms, and Courier), so nothing is bundled and nothing is downloaded. It
  lays out what the reports use: headings, paragraphs, lists, tables that repeat their header row on each page and
  split a row taller than a page, code, links, bold and italic text, and "Page n of N" on each page. Headings become
  bookmarks. Every byte is ASCII (the text in hexadecimal, the page streams not compressed), so it is text the tests
  read back with the standard library alone, and it passes through every path the other report files take.
- **US Letter by default,** as in v1, and A4 when stackvet.toml says `report-paper = "a4"` under `[app]`. A setting in
  the file rather than an option, so the MCP server's reports and the bundle's follow it too.
- **The limit, said plainly.** The standard fonts show Western European letters and common punctuation only. A few
  arrows and signs are spelled in ASCII (`->`, `>=`), and any other character prints as `?`. The PDF's first page
  says so, and that `report.html` is the complete version. A test fails when `sv`'s own words or data use a character
  the fonts lack, so it is found, not printed wrongly.
- **`report.html` and `security.md` name the PDF** and the paper it is on, as they name the SARIF file and the bill of
  materials.

## Alternatives considered

- **A PDF library crate:** full Unicode and embedded fonts, at the cost of a new dependency tree and a larger
  binary. The change to make if the character limit turns out to matter for the people `sv` is for.
- **Printing through the person's browser:** rejected in v1, because no file exists until somebody makes one, and
  the result differs between machines.
- **A PDF only on request:** rejected, because the point is a file people can open without knowing to ask for it.
- **`compliance.md` and `security.md` joined:** rejected by the owner, because their shared parts would print twice.
- **Compressed page streams:** half the size, but the file would no longer be text a test can read back without a
  decompressor, and `sv` would need one; a report of fifty pages is under a megabyte as it is.

## Consequences

- One more file in every report folder and bundle, about 0.6 to 0.9 MB for the example apps' reports (45 to 60 pages).
- The PDF says nothing new and credits nothing: no status, count, or tier moves.
- Held by `crates/sv-cli/tests/report_pdf.rs`: on every example app's report, every ordinary word of `security.md` and
  `compliance.md` is in the PDF, nothing is drawn past the margin on either paper, `sv`'s own words use only
  characters the fonts have, and the file is in the report folder and the bundle and follows `report-paper`.
  `crates/sv-report/src/pdf/pdf_tests.rs` holds the reader, the repeated header row, the split row, the bookmarks,
  and the links, and refuses a file whose table of objects is wrong. Each was broken on purpose and caught.
