# ADR-115: CodeQL runs only when the owner turns it on, for the uses its license allows

**Status:** accepted, 14 October 2026, in the pull request that builds it (backlog 0415). The decision is the owner's,
13 October 2026, option B of three: "agree, let's go with B please". Written by session honesty.

**Governs:** `data/adapters.json` (the opt-in field on CodeQL's three adapters),
`crates/sv-check/src/adapters.rs::opted_in` (the filter), `crates/sv-manifest/src/lib.rs` (the tools section of
stackvet.toml), `crates/sv-cli/src/assemble.rs` (where the outside tools are filtered by it), and `tools/coverage.py`
(the kind of check for tools the owner turns on). A pull request that changes what these run or count by default
changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

`sv` ran CodeQL with the other outside tools whenever it was installed, and a report made without it said so under
"What was not examined", with how to install it. Read on 13 October 2026, CodeQL's terms
(github.com/github/codeql-cli-binaries, `LICENSE.md`) allow it for academic research, for demonstrating it, and on an
"Open Source Codebase", one released under an OSI-approved license; any other code needs a paid GitHub Advanced
Security license, and automated analysis or CI is allowed only on open source hosted on GitHub. Most of StackVet's
users build private apps, so every report pointed them at a tool they may not use on that app. CodeQL speaks to 31
ASVS requirements; five only it reaches (V1.2.2, V1.2.9, V15.3.5, V15.3.6, V16.4.1), and it follows data across files,
which pattern matching does not.

The owner was offered three ways: A, take CodeQL out; B, keep it, off unless the owner turns it on; C, keep it as it
is. The owner chose B, and asked that a report made without it neither say CodeQL did not run nor list it as a tool
to install.

## Decision

1. **`[tools] codeql = true` in `stackvet.toml` turns CodeQL on.** Its description there, in the README, the guide,
   and the website says what the license allows: an app released under an open-source license, academic research, or
   a paid GitHub Advanced Security license. `sv` cannot tell which applies; the owner who turns it on is saying one
   does.
2. **Off, CodeQL is not run and not named.** CodeQL's three adapters carry `opt_in` in `data/adapters.json`, and
   `Adapters::opted_in` leaves out every adapter whose setting is off before the outside tools run, so it is in
   neither "What was not examined" nor "Outside tools", not in the screen's lines, and not in what a run without the
   tools names. Its requirements stay as whatever else shows them, and the five only it reaches stay not verified, as
   they were when it was missing.
3. **On and missing, the report says so with how to install it,** as before.
4. **The counts say what a default run reaches.** `tools/coverage.py` counts a tool the owner turns on under a kind
   of check of its own, "Outside tools you turn on", so `docs/COVERAGE.md` and `data/reach.json` keep it apart from
   the tools that run by default, and the report's count of what a run without the tools would have reached leaves
   it out.
5. **A results file from the owner's own CI is still read** (`--codeql-results`, ADR-113): that runs nothing here,
   and giving the file is the owner's own choice.

## Consequences

- A report on a private app no longer sends its owner to a tool they may not use on it.
- A default run reaches five ASVS requirements fewer than one with CodeQL turned on; `docs/COVERAGE.md` names them.
- The test is `off_codeql_is_not_run_and_not_named_and_on_it_is` in `crates/sv-cli/tests/tools_turned_on.rs`: off,
  no file the run writes and nothing it prints names CodeQL or its adapters; on, it is named. It fails when the
  setting is ignored. The tests about CodeQL's place among the tools turn it on for themselves.
