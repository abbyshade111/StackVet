# ADR-145: The dynamic-code rule reads Rust's embedded interpreters, and a clean Rust app is credited in part

**Status:** proposed, 24 October 2026, with the claim for the last rule of backlog 0661; accepted in the pull request
that builds it.

**Governs:** `data/ast-rules.json` (the Rust query of `ast.dynamic-code-execution`, and its Rust words) and its
witnesses (`crates/sv-check/src/ast/tests.rs`). A pull request that changes which Rust interpreters the rule reads, or
whether a clean Rust result credits V1.3.2, changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

`ast.dynamic-code-execution` (V1.3.2, code built at run time and executed) is one of the few code rules that credits a
requirement when it finds nothing, and it credits it in part (`inPart`). Rust is listed as having nothing to find:
"Rust has no built-in way to run a string as code. An embedded interpreter such as rhai would be one, and is not
looked for." So a Rust file never stops the rule from claiming anything in a mixed app; but a Rust-only app gets no
clean claim at all, because no Rust file is read for it. Backlog 0661 asks for the embedded interpreter to be looked
for.

## Decision

- **The rule reads Rust's embedded interpreters:** rhai's `Engine` (`eval`, `eval_expression`, `eval_with_scope`,
  `run`, `run_with_scope`, `compile`, `compile_expression`), mlua's `Lua::load`, boa's `Context::eval`, and
  deno_core's `execute_script`, on a receiver named for the engine (`engine`, `lua`, `context`, `runtime`, and the
  like), given code that is not fixed text in the code. A script written out in the code is safe, as in every other
  language.
- **The Rust "nothing to find" entry goes,** replaced by the query, so a Rust file is read like any other language's.
- **A clean Rust-only app is now credited in part with V1.3.2,** as an app in any other language is, with the words
  saying what was looked for in Rust: those interpreters' calls. The credit stays "in part": a script loaded from a file
  and run, or an interpreter the list does not name, is not seen, and the words say so.

## Alternatives considered

- **Leave Rust as nothing to find.** Rejected: an app that embeds rhai to run what a person typed has the fault, and
  is told nothing.
- **Mark the Rust half findings-only, so it never credits.** Rejected: every other language's reading credits in part
  on the same terms; Rust has fewer ways to run text as code than they do, not more, so withholding the credit would
  understate what was checked.

## Consequences

- A Rust app that runs a person's text through rhai, mlua, boa, or deno_core is told so.
- A Rust-only app with none of these gets V1.3.2 checked in part where before it had no word on it; a mixed app's
  result is unchanged unless its Rust code has one of these calls.
