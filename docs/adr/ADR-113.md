# ADR-113: A CodeQL results file from the owner's own CI is read when given, and credited only for the commit checked out

**Status:** accepted, 14 October 2026, in the pull request that builds it (backlog 0274). The decision is the owner's,
9 October 2026, recorded in backlog 0147 part 7 (asked by session securevibe-e2): yes to reading a CodeQL SARIF file
from the owner's own CI, as recommended; a clean result is credited only when the file's commit is the commit of the
code being checked, and any other file is reported and credits nothing. Written by session honesty.

**Governs:** `crates/sv-check/src/ci_codeql.rs` (how the file is read and what it credits), `crates/sv-check/src/git.rs::head_commit`
and `crates/sv-check/src/git.rs::has_uncommitted_changes` (the app's commit), and the option of sv report that
names the file, in `crates/sv-cli/src/main.rs`, declared in `crates/sv-cli/src/commands.rs`. A pull request that changes what these read or credit changes this record
too, or says in its description why it does not (`docs/adr/README.md`).

## Context

`sv` runs CodeQL itself, offline, for JavaScript and TypeScript, Python, and Ruby (ADR-078), and reads the SARIF it
writes. Many owners already run CodeQL in their CI, on GitHub or elsewhere, and its results file reaches the same
rules from a run `sv` did not make. A file is only a claim about the code it was made from: a clean file of last
week's commit says nothing about today's code, and one with a commit that cannot be read says nothing about any.

## Decision

1. **`sv report --codeql-results FILE`** reads a SARIF file the owner gives, whether or not the outside tools run (it
   is a file, not a program). `sv` opens no connection for it: the owner downloads the file from their CI. The
   MCP server does not take it.
2. **Each CodeQL run in the file is read only for the commit checked out.** The run's commit is its
   `versionControlProvenance[].revisionId`, which CodeQL writes. The app's is `git rev-parse --verify HEAD` in its
   folder, run with the overrides ADR-032 records. The two must be the same, and no file git tracks may have changed
   since. That is read with `git ls-tree -r HEAD`, which gives each file's id in the commit, and each file here hashed
   the way git names its content, with no filter: not with `git status` or `git diff`, which run the repository's
   clean filter, a program its `.git/config` names (ADR-032, Later, 14 October 2026). A repository that filters its
   files (line endings, large-file storage) reads as changed and is credited nothing, and one with a submodule reads
   as unknown. Files git does not track are left out, as a commit says nothing of them either way.
3. **A run that is read counts as `sv`'s own CodeQL run would.** It is matched to the codeql-javascript,
   codeql-python, or codeql-ruby map by its rule ids. Its results are findings. A run with none, that looked at all of
   the app, credits what its loaded rules map to, as `clean_run_evidence` decides for any run. The credit is the same
   check (`adapter.codeql-…`) and says it came from the owner's CI, the file, and the commit.
4. **Any other run is said and read for nothing.** That covers a run with no commit, another commit, changes since,
   an app folder that is not a git checkout, a language with no map (Go, Java, and the rest), another tool's run, and
   a file that is not SARIF. Each is a gap in the report, naming the file and why. Its results are not shown, since
   they may be of code changed since, and its silence credits nothing. A run of another commit or with changes since
   is an `Outdated` gap; one with no map, `NoReader`; one that cannot be read, `CouldNotRead`.

## Consequences

- An owner whose CI runs CodeQL gets its credit in a report made on the same commit, with no CodeQL on their computer.
- A file read beside `sv`'s own CodeQL run of the same language gives the same credit twice, from two runs; both are
  true, and neither is counted as more.
- Trusting the file is trusting that it is CI's own and of the commit it names: `sv` cannot check either beyond what
  the file says. A file the owner edits by hand to name today's commit would be believed, as a hand-written
  `stackvet.toml` answer is; the credit says where it came from.
- Go and Java results from CI are not read, since `sv` has no map of their rules to requirements; a map for them is
  the way to add them, as a backlog item of its own.
