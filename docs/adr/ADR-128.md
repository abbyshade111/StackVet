# ADR-128: A Dependabot pull request that only moves pins owes the decision records no line

**Status:** accepted, 20 October 2026, in the pull request that builds it; proposed the same day with the claim for
backlog 0617.
The owner's choice of 20 October 2026, asked in a session: "Auto-pass, diff-verified", over writing the lines into the
description by a workflow, or keeping them by hand.

**Governs:** `tools/adr_check.py::pin_only`, `tools/adr_check.py::PIN_LINES`, `.github/dependabot.yml`. A pull request
that changes these changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

The required "Decision records" check (ADR-061, ADR-103) asks every pull request that touches a governed file to change
the record or say why not. The workflows, `action.yml`, both Dockerfiles, and `tools/py7zr-requirements.txt` are
governed, and they are what Dependabot moves. On 20 October 2026 every one of its seven open pull requests (#2139 to
#2145) failed the check, and each earlier one had waited for a session to write its lines by hand. The lines said the
same thing each time: a pin moved, and the decision stands.

## Decision

- **A pin-only Dependabot pull request owes nothing.** `tools/adr_check.py` treats a governed record as unchanged when
  the pull request's author, read from the event file, is `dependabot[bot]`, **and** every line the diff adds or
  removes is a pin (`PIN_LINES`): a step's `uses: owner/name@<40 hex> # vX`, a `FROM image:tag@sha256:<64 hex>`, a
  requirement's `name==version` or its `--hash=sha256:` lines, any line of a file named `Cargo.lock`, or a
  requirements file's `# via ...` line. A comment anywhere else asks.
- **The diff is what is trusted, not the author.** A commit pushed onto a Dependabot branch that changes anything else,
  or a `Cargo.toml` requirement (a dependency, which `CLAUDE.md` counts as a decision), makes the check ask as it does
  for anyone. The author test only narrows who can qualify.
- **Choices Dependabot cannot make stay out of its reach in its configuration,** not in the check: Node's major
  (ADR-019, Later, 13 October 2026) is ignored under both of the names Dependabot has used for it, `node` and
  `library/node`.
- **What moves together is proposed together.** The cargo entry covers `/fuzz` beside `/`, so the fuzz lock (ADR-077)
  is not left behind a bump.

## Consequences

A pin-only update is merged on its tests alone. A record that governs a workflow learns nothing from a step's new
fingerprint, which is the case this narrows.

What it does not see, since the check reads each changed line without its sign:

- **A new major.** A step or image that changes what it does arrives as a new major, whose line is still a pin, so
  the weekly review of the records stays the place that reads release notes. Node's major, the one the owner holds, is
  kept out in the configuration instead.
- **A new package in a lock or the requirements file.** A grouped update that pulls in a package not there before
  writes lines of the same shapes. A new direct dependency needs a `Cargo.toml` line, which still asks; a new
  indirect one, pulled in by a newer version of a crate already there, passes, as it did before this record for a
  lock-only bump (#1628), since no record governs `Cargo.lock`. In `tools/py7zr-requirements.txt` it is a package
  py7zr now needs, installed only in CI and held to its hashes.
