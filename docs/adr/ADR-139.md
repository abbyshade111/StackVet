# ADR-139: One reading of test code for every check

**Status:** proposed, 23 October 2026, with the claim for backlog 0654, at the owner's answer of that day to backlog 0647's choices, asked how StackVet should tell a real fault from the
false alarms its path rule raised on its own code: all three test-code fixes. It becomes
accepted in the pull request that builds it.

**Governs:** while proposed, the claim it is made with, `docs/backlog/0654-one-reading-of-test-code-for-every-check-rust-s-test-modules.md`; the pull request that builds it
replaces that with the files it changes. A pull request that changes how any check reads a file, or part of one, as test code changes this record too,
or says in its description why it does not (`docs/adr/README.md`).

## Context

Test code is read three ways. The code rules mark a finding in test code and list it apart, where it still counts
(ADR-023), by folder and name and, for Rust, by `#[cfg(test)]` (ADR-136). Nine checks skip test files by name alone,
and none of them knows a Rust test module in `src/`. And `#[cfg(all(test, unix))]`, on 12 of StackVet's own test
modules, is read by neither (backlog 0652).

## Decision

- **One reading, in `sv-scan`, that every check uses:** test code by folder and name, as now; by `#[cfg(...)]` lines in
  a Rust file and the line that declares a module (ADR-136); and by a condition that holds only in a test build, `test`
  or `all(...)` with `test` among its own arguments. Never `any(test, ...)`, and never `test` under `not` or `any`.
- **What each check does with it is unchanged:** the code rules list such a finding apart and it counts; the checks that
  gather evidence of what the app uses skip it, now including Rust's test modules.
- **The weak-key check** reports in test code and lists the finding apart, as the code rules do, rather than skipping
  (backlog 0655, a Later entry on ADR-137).
