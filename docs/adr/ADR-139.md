# ADR-139: One reading of test code for every check

**Status:** accepted, 23 October 2026, in the pull request that builds it; proposed the same day with the claim for
backlog 0654, at the owner's answer of that day to backlog 0647's choices: all three test-code fixes, among them "One
reading for all checks".

**Governs:** `crates/sv-scan/src/rust_tests.rs`, `crates/sv-scan/src/files.rs::is_test_code`,
`crates/sv-check/src/finding.rs::mark_rust_test_code`, `crates/sv-check/src/finding.rs::marks_test`, and the checks that
read test code through the listing (`crates/sv-check/src/crypto_inventory.rs`, `crates/sv-check/src/outbound_rules.rs`,
`crates/sv-check/src/route_guards.rs`, `crates/sv-check/src/personal_fields.rs`, `crates/sv-check/src/session_settings.rs`,
`crates/sv-check/src/sign_in_paths.rs`, `crates/sv-check/src/weak_keys.rs`, `crates/sv-check/src/level_hints.rs`,
`crates/sv-scan/src/imports.rs`), with their tests (`crates/sv-scan/src/rust_tests_tests.rs`). A pull request that
changes how any check reads a file, or part of one, as test code changes this record too, or says in its description
why it does not (`docs/adr/README.md`).

## Context

Test code is read three ways. The code rules mark a finding in test code and list it apart, where it still counts
(ADR-023), by folder and name and, for Rust, by `#[cfg(test)]` (ADR-136). Nine checks skip test files by name alone,
and none of them knows a Rust test module in `src/`. And `#[cfg(all(test, unix))]`, on 12 of StackVet's own test
modules, is read by neither (backlog 0652).

## Decision

- **One reading, in `sv-scan`, that every check uses:** test code by folder and name, as now; by `#[cfg(...)]` lines in
  a Rust file and the line that declares a module (ADR-136); and by a condition that holds only in a test build, `test`
  or `all(...)` with `test` among its own arguments. Never `any(test, ...)`, and never `test` under `not` or `any`.
- **What each check does with it is unchanged:** the code rules list such a finding apart and it counts; the checks that
  gather evidence of what the app uses skip it, now including Rust's test modules.
- **The weak-key check** reports in test code and lists the finding apart, as the code rules do, rather than skipping
  (backlog 0655, a Later entry on ADR-137).

## Where the build differs

- **Read from the text, in `sv-scan`, without a parser.** `sv-scan` has no Rust grammar, and adding one would be a new
  dependency; a module's declaration has one shape (attributes, then `mod name;`), so it is read off the file's top
  level, with comments, strings, character literals, and everything inside braces passed over. 0644's parser in
  `sv-check` is replaced by it, so the code rules and every other check read the same declarations (ADR-136, Later).
  The line ranges inside a file (`#[cfg(test)] mod tests { ... }`) are still read by `sv-check`'s parser, the only
  place that needs them, with the same rule for a `cfg`.
- **Through the listing.** `Listing::is_test_code` answers for a file, and the answer is shared by every copy of the
  listing and both halves of a `split`, read from the folder on disk so a declaring file in the other half still counts.
  The import reading (`sv-scan`'s technology scan) takes it too, so a Rust test module's imports are a test's, not the
  app's.
- **The weak-key check still skips test code,** now including Rust's; reporting it there instead is backlog 0655.
- **Held by** `rust_tests_tests.rs`: with `all(...)` not read as test-only, all three of its tests fail; with blocks
  not passed over, the declaration test fails; with the listing reading names alone, the listing test fails.

## Later, 26 October 2026 (the fifth weekly review)

The line "the weak-key check still skips test code, now including Rust's; reporting it there instead is backlog 0655" was untrue within the day. Commit `8a371fc` (23 October, ADR-137, Later) made the check read test code and list the finding apart (`crates/sv-check/src/weak_keys.rs`). The Decision's own bullet, "reports in test code", is the true one.
