# ADR-094: The report says what Docker read of the app's container, and it decides no requirement

**Status:** accepted, 11 October 2026. The owner approved building backlog 0243 on 11 October 2026: `sv run` takes
resource readings of the app's container and writes them to the report beside the AI probe's unchecked quotas. The
reading and taking steps landed first (#1464, #1466), each saying this record would come with the step that changes
what a report says. This is that step.

**Governs:** `crates/sv-run/src/resources.rs` (the readings, and the words the report and the printout use for them),
`crates/sv-cli/src/lib.rs` (where the readings join C9.1.1's note), and `crates/sv-check/src/ai.rs` (the C9.1.1 note
they join), `crates/sv-run/src/docker.rs`. A pull request that changes these changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

AISVS C9.1.1 asks that an AI app limit its tools' execution time and their use of CPU, memory, disk, and network. The AI
probe can see a time limit from outside, so it credits that part and says the rest is not assessed. `sv run` starts the
app's container from the host, and the research of 11 October 2026 (backlog 0243) found that Docker reports the
container's CPU, memory, network, and disk use and the CPU and memory limits it was started with, in about a second,
without touching the app.

## Decision

- **Said as information.** After the run's probes and before its containers are removed, `sv run` takes one reading.
  The report's note on how the app was run, and `sv run`'s printout, say it in the engine's own units: CPU as a
  percentage of one CPU, memory used against what it could use, network and disk traffic since the container started,
  and the limits it started with or that it had none.
- **It decides no requirement.** The numbers are the whole container's, at one moment, taken from outside. C9.1.1 asks
  for limits the app puts on its own tools, which these do not show, so no requirement's status or credit changes. The
  sentence says so.
- **Beside the quotas.** When the reading was taken, C9.1.1's note that the tools' CPU, memory, disk, and network use
  was not checked gains a sentence: the run did read the container's own use, and that does not change the note. The
  note is matched by its name (`sv_check::ai::UNSEEN_QUOTAS`), not by its words.
- **Absence is said.** When Docker would not answer, or answered in words `sv` does not read, the report says Docker did
  not say, and the C9.1.1 note is left as it was. No number is guessed.
- **Nothing leaves the computer.** Two read-only commands to the local engine, `docker stats --no-stream` and
  `docker inspect`. The app and its network fence are not touched.

## Alternatives considered

- **Credit C9.1.1 in part from the limits.** A container limit is set by whoever starts the container, here `sv`'s own
  run or the platform it is deployed on, not by the app, and it bounds the whole app rather than one tool. Crediting it
  would make the check look stronger than it is.
- **Two readings, for rates.** Egress and disk are totals since the container started; a rate needs a second reading and
  the time between. One reading answers what was asked and adds no wait to the run. Left for later if a rate is wanted.
- **A disk quota.** The engine reports none for a container started without one, and a quota set outside `sv` did not
  show in the research. Not reported rather than guessed.

## Consequences

- Every report of an app `sv run` started gains one sentence about its container's resources, or one saying Docker did
  not say. No count, status, or headline changes.
- The numbers describe `sv`'s own run on the owner's computer, not the app where it is deployed.
