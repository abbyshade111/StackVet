# ADR-141: stackvet.toml sets environment variables for the copy of the app `sv` runs, and the starter stops putting the app's data under /tmp

**Status:** accepted, 24 October 2026, in the pull request that builds it; proposed on 23 October 2026 with the claim
for backlog 0659, at the owner's word of that day: "yes, file it as 0659 and build it after 0658 please", after asking
whether StackVet itself makes apps prone to their findings.

**Governs:** `crates/sv-manifest/src/lib.rs::RunSection` (its env table), `crates/sv-run/src/lib.rs::run_env`,
`crates/sv-run/src/lib.rs::SET_BY_SV`, where the app's container is started (`crates/sv-run/src/docker.rs`), the
starter's words (`crates/sv-manifest/src/spec.rs`), the preflight's word on it (`crates/sv-cli/src/preflight/data_folder.rs`),
and their tests (`crates/sv-run/src/env_tests.rs`, `crates/sv-cli/src/preflight/data_folder_tests.rs`). A pull request
that changes which variables stackvet.toml may set for the app's container, or what the starter tells an app about
where to keep its data, changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

`sv` runs the app with its folder read-only, and its container can write only `/tmp` and `/sv-reports`. The starter
manifest told the AI coding tool "keep its data somewhere like /tmp", and stackvet.toml had no way to give `sv`'s copy
a variable of its own, so the only way to follow the advice was to make `/tmp` the app's default. Backlog 0648's survey
found that default in 8 of 12 apps, reported by Bandit as B108; in production `/tmp` is shared with every user of the
machine and emptied on reboot. This is `sv` shaping the code it checks.

## Decision

- **`[stack.run] env`** is a table of variables set in the app's container for `sv`'s run: `env = { DATABASE_PATH =
  "/tmp/app.db" }`. They are passed to the app alone: not to the install step, the seed, or the tests' host, unless a
  later record says so. A variable `sv` sets itself (`PORT`, and those it sets for the helpers it starts) cannot be
  replaced, and is refused with a plain message.
- **No credential in it.** A name that says it holds a key, a password, or a token, or a value that looks like one, is
  refused, as the manifest refuses one everywhere else; a value the app needs that must not be written there is
  printed by the seed (ADR-124).
- **The starter's words change** to: keep the data folder configurable by an environment variable, with the default
  the real app should use, and point `sv`'s copy at `/tmp` through `[stack.run] env`.
- **The preflight says** when the app's data defaults to `/tmp`, and how to move it to `env`. It is advice, read from
  the text, and decides nothing.
- What the report concludes is unchanged: B108 still reports a fixed `/tmp` path where it finds one.

## Where the build differs

- **The seed and the tests see the variables too.** They run in the app's own container (`docker exec`), so they see
  what the app sees, which is right for them; the install step runs in a container of its own and does not. The
  proposal had said the seed and the tests would not.
- **A credential is refused by its name; its value is the secrets scan's.** The manifest does not refuse a value
  anywhere else (the proposal said it did): a key-like value in stackvet.toml is a finding of the secrets scan, which
  reads the file like any other. So `env` refuses a name holding `KEY`, `SECRET`, `TOKEN`, `PASS`, `CREDENTIAL`,
  `AUTH`, `PRIVATE`, `COOKIE`, or `SALT`, and a value that looks like a key is reported as it would be anywhere in the
  file. A Flask app's `SECRET_KEY` is refused, so such an app needs a default of its own for `sv`'s copy, as it did
  before.
- **What `sv` sets itself:** `PORT`, `PATH`, `PYTHONPATH`, `NODE_PATH`, the three `SMTP_` and three `OIDC_` variables,
  any `SV_` name, and the variables the manifest names for the test model and the MCP server's token. A value may not
  hold a line break or a NUL. Each refusal stops the run with a plain message naming the variable, and everything that
  needs the app running is reported as not assessed.
- **Checked without a pattern library:** `sv-run` needs none otherwise, and a new dependency was not worth two checks.
- **Held by** `env_tests.rs` (each refusal, and a plan carrying what it accepts): with the credential check taken out,
  `SECRET_KEY` is let through and the test fails; with the reserved names taken out, `PORT` is. The variables reaching
  the container are passed as `-e` arguments on the one `docker run` that starts the app; no test starts a container
  for them.
