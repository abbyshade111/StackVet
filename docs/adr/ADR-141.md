# ADR-141: stackvet.toml sets environment variables for the copy of the app `sv` runs, and the starter stops putting the app's data under /tmp

**Status:** proposed, 23 October 2026, with the claim for backlog 0659, at the owner's word of that day: "yes, file it
as 0659 and build it after 0658 please", after asking whether StackVet itself makes apps prone to their findings. It
becomes accepted in the pull request that builds it.

**Governs:** while proposed, the claim it is made with, `docs/backlog/0659-the-starter-tells-the-ai-tool-to-keep-the-app-s-data-under.md`; the pull request that builds it replaces that with
the files it changes. A pull request that changes which variables stackvet.toml may set for the app's container, or
what the starter tells an app about where to keep its data, changes this record too, or says in its description why
it does not (`docs/adr/README.md`).

## Context

`sv` runs the app with its folder read-only, and its container can write only `/tmp` and `/sv-reports`. The starter
manifest told the AI coding tool "keep its data somewhere like /tmp", and stackvet.toml had no way to give `sv`'s copy
a variable of its own, so the only way to follow the advice was to make `/tmp` the app's default. Backlog 0648's survey
found that default in 8 of 12 apps, reported by Bandit as B108; in production `/tmp` is shared with every user of the
machine and emptied on reboot. This is `sv` shaping the code it checks.

## Decision

- **`[stack.run] env`** is a table of variables set in the app's container for `sv`'s run: `env = { DATABASE_PATH =
  "/tmp/app.db" }`. They are passed to the app alone: not to the install step, the seed, or the tests' host, unless a
  later record says so. A variable `sv` sets itself (`PORT`, and those it sets for the helpers it starts) cannot be
  replaced, and is refused with a plain message.
- **No credential in it.** A name that says it holds a key, a password, or a token, or a value that looks like one, is
  refused, as the manifest refuses one everywhere else; a value the app needs that must not be written there is
  printed by the seed (ADR-124).
- **The starter's words change** to: keep the data folder configurable by an environment variable, with the default
  the real app should use, and point `sv`'s copy at `/tmp` through `[stack.run] env`.
- **The preflight says** when the app's data defaults to `/tmp`, and how to move it to `env`. It is advice, read from
  the text, and decides nothing.
- What the report concludes is unchanged: B108 still reports a fixed `/tmp` path where it finds one.
