# ADR-100: `sv report` says how long each slow stage took as it ends, and `--quiet` silences the progress

**Status:** proposed, 12 October 2026, in the claim of backlog 0247. The owner's word the same day, asked which of
three parts to build: "all three", and that progress should be printed "regardless of what tool someone is using".
They had seen a quiet terminal while running `sv` from Cursor.

**Governs:** `crates/sv-cli/src/main.rs` (what the report command prints, and its switches) and `crates/sv-cli/src/assemble.rs`
(the stages). A pull request that changes what these print while a run goes on changes this record too, or says in its
description why it does not (`docs/adr/README.md`).

## Context

Much of what backlog 0247 asks was built before it was filed (backlog 0226, part 2, items 13 and 15):

- `sv report` prints a line on stderr as each of its ten stages starts (`REPORT_STAGES`, `stage_line`), whether or not
  stderr is a terminal, so it shows in whatever runs `sv`.
- Each stage, each outside tool, and each suite of questions to the running app is timed, and every report page names
  the five slowest parts at its top (`slowest_line`); the JSON report holds every timing.
- The MCP server sends the same stages as progress notifications.

Not built: the terminal never says how long a stage took, and there is no way to turn the lines off.

## Decision (proposed)

- **A stage's time, as it ends.** A stage that took five seconds or more is followed by a line on stderr saying how long
  it took, in minutes and seconds. Shorter stages print nothing more, so a quick run reads as before.
- **The slowest parts at the end, in the terminal too.** The line the report pages start with is printed after the run,
  beside the counts.
- **`--quiet`.** `sv report --quiet` prints none of the progress or timing lines. The files written, the counts, and any
  error still print: it quiets the progress, never what the run concluded.
- **Progress in the report** is the timing the report already carries; nothing more is added to it.
- **Regardless of the tool.** The lines go to stderr whatever runs `sv`, as now. When an AI coding tool holds a
  command's output until it ends, or does not show the MCP server's progress notifications, `sv` cannot change that;
  the report's timing line is then where the times are seen.

## Consequences

- A person watching a long run sees which stage is slow, and for how long, without opening the report.
- None of this changes what a report concludes.
