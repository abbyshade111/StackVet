# ADR-100: `sv` keeps two files of its own, an opt-in log and a crash file, and never puts an argument or a path in either

**Status:** accepted, 12 October 2026, written by the third weekly review of the decision records, three days after the
build (#1399, 10 October). The decision is the owner's, of 10 October 2026, asked with the other open decisions of that
day (backlog 0237, observability review part 3, I); the reasons below are those the design entry gives
(`docs/design/0366-files-of-sv-s-own-an-opt-in-log-and-a-crash-file-10-october.md`). The owner's own reasons were
not written down beyond "yes".

**Governs:** `crates/sv-cli/src/own_log.rs` and `crates/sv-cli/src/crash.rs`, which write the two files. A pull request
that changes these changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

Until 10 October `sv` wrote into the owner's computer only what ADR-017 lists (the report folder, the review entries,
the history the owner asks for). When a run failed or was slow, nothing of `sv`'s own was left to read, and the
observability review (backlog 0226) asked for something.

## Decision

- **`SV_LOG`, when set to a path, is a file `sv` appends to.** Each line has the time, a report stage's name, and the
  command's name. Never an argument, a path the owner typed, or anything a report says. A line that cannot be written is
  dropped, and without `SV_LOG` nothing is written.
- **A crash file under the history folder, when a panic reaches the top of a run.** It holds the version, the command's
  name, and the place of the panic (the file and line in `sv`'s own source). Never the panic's message, which can name a
  path or a value; the terminal shows that to the owner when it happens.
- **The promise is the point.** "Never arguments, never paths, never a message" is a privacy commitment: these files
  are the ones a person may paste into a bug report. Widening what either holds is a decision, not a log tweak.

## Alternatives considered

- **Always log.** It would write into the owner's computer unasked, against ADR-017's rule that `sv` writes only what it
  lists.
- **Keep the panic's message.** More useful to a reader, and it is where a path or a value appears.

## Consequences

- Two more things `sv` writes outside the app's folder (ADR-017's list gains them).
- A crash leaves a place to look; a failure that is not a panic leaves nothing.

## Tested

`crates/sv-cli/tests/own_files.rs`: `sv_log_names_the_stages_and_the_command_and_not_the_paths`,
`without_sv_log_no_log_is_written`, and `a_panic_leaves_a_crash_file_with_the_command_and_its_place_and_no_arguments`.
