# ADR-124: A value the sign-up needs and the manifest must not carry is printed by the seed and cited as `{seed:NAME}`

**Status:** accepted, 16 October 2026, in the pull request that builds it (backlog 0536). The decision is the owner's,
14 October 2026, choice (a) of three: "the seed-made value: the manifest's seed command prints NAME=value lines and the
sign-up form cites {seed:NAME}; the value is made inside the fence at run time and never written down. A new ADR in the
pull request that builds it (what sv reads at run time and what the manifest may cite)." Written by session honesty.

**Governs:** `crates/sv-run/src/docker.rs::seed_values`, `crates/sv-check/src/script.rs::keep_out`,
`crates/sv-check/src/signed_in/mod.rs::fill_seed`, `crates/sv-check/src/signed_in/mod.rs::seed_names`, the
`seed_values` field of `crates/sv-check/src/signed_in/mod.rs::Accounts`, and the `{seed:NAME}` lines in
`crates/sv-manifest/src/spec.rs`. A pull request that changes what `sv` reads from the seed, what the manifest may
cite, or where such a value may appear, changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

In the three-tool trial of 14 October 2026 (backlog 0502), one app gated its sign-up on an invite code read from its
environment. The AI coding tool rightly kept the code out of `stackvet.toml`, and every sign-up `sv` sent was refused
with a 403, so the checks that make an account of their own ran without one. Another tool wrote a fixed test code into
the app and the manifest, which worked and is itself a weakness.

## Decision

- **What the seed may print.** Besides making the accounts, the manifest's `seed` command may print lines of the form
  `NAME=value` (a name of letters, digits, and `_`, not starting with a digit; an optional `export ` before it; quotes
  around the value taken off). `sv` reads them from what the seed printed when it succeeded, inside the app's own
  container, at run time. Any other line is the seed's own talk and is not read.
- **What the manifest may cite.** A request in `[stack.run.users]` may cite such a value as `{seed:NAME}`, in a field
  or its path: `invite_code = "{seed:INVITE}"`. The value itself is never written in the manifest. A manifest that
  cites `{seed:…}` in `signup` or `login` with no `seed` is refused, by name, before anything runs.
- **Where the value goes.** Into the requests that cite it, and nowhere else. A name the seed did not print is sent
  as written, so the app refuses it, and the run says which name was missing.
- **Where it may not appear.** Request bodies were never kept. The value is also taken out of everything else the run
  writes down: the steps, the reasons for what was not assessed, findings, credits, every recorded answer's path,
  headers, and body, and the app's log lines kept beside the report. In each place it is shown as "[a value the seed
  printed]". A seed that printed a value and then failed has that value left out of the failure's words too. A value
  shorter than four characters is not looked for, since it would match ordinary text; such a value is not a secret
  worth the name.
- **The network fence is unchanged.** Nothing new is fetched or sent outside: the value is made inside the fence and
  used inside it.

## Alternatives considered

- (b) An environment variable the manifest names (`{env:NAME}`), read from the person's own environment at run time.
  Not chosen: it carries a value from outside the fence into the run, and the person's environment is theirs.
- (c) Leave it: preflight says a sign-up field with no value will refuse `sv`'s accounts, and the app accepts a test
  code when `STACKVET_RUN=1`. Not chosen: it asks the app to carry a back door for the run.

## Consequences

- An app whose sign-up needs a code can be checked fully, with the code kept out of every file.
- The seed must be able to print the value: from the app's environment inside its container
  (`echo "INVITE=$FAMILY_INVITE_CODE"`), or by making one.
- Held by `crates/sv-check/src/signed_in/seed_values_tests.rs`, `crates/sv-check/src/script/seed_keep_out_tests.rs`,
  `crates/sv-run/src/seed_failure_tests.rs`, and `crates/sv-manifest/src/seed_value_tests.rs`.
