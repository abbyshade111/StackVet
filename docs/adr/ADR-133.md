# ADR-133: AC.4.1 credits a review by hand only when the reviewer is not the person who asked for the code

**Status:** accepted, 23 October 2026, in the pull request that builds it; proposed the same day with the claim for
backlog 0641, at the owner's answer of that day, asked in a session what StackVet should do when the owner records a
review of code they asked for: "Ask who reviewed".

**Governs:** `crates/sv-check/src/hand.rs::SEPARATE_REVIEW`, `crates/sv-check/src/seal.rs::hand_check_fields`,
`crates/sv-cli/src/review.rs::ask_reviewer`, `crates/sv-cli/src/assemble.rs::separate_review_gap`, and their tests
(`crates/sv-cli/src/review/separate_review_tests.rs`, `crates/sv-cli/tests/separate_review.rs`). A pull request that
changes what counts as a review by hand for AC.4.1 changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

AISVS 1.0 Appendix C's AC.4.1, as StackVet carries it: "Verify that AI-generated code always goes through code review
by a qualified human engineer. The reviewer must not be the same identity that asked for the AI generation in the
first place (separation of duties). And the AI agent itself does not count as the human reviewer." In the owner's
Cursor build of 22 October 2026, the owner, who asked for the code, answered "I've looked at the files and code cited
for each of the checks", the AI tool recorded it as done, `sv review` confirmed it, and the report credited AC.4.1 as
checked by hand. The owner's word was recorded honestly; the credit said more than the requirement allows.

## Decision

- **`sv review` asks who reviewed** when it confirms a check by hand for AC.4.1: whether the reviewer is someone other
  than the person who asked the AI tool for the code. The question is asked in the owner's own terminal, as every
  confirmation is, and the answer is sealed with it.
- **Someone else:** credited as checked by hand, as now, with the reviewer recorded by role (never by name).
- **The person who asked:** recorded as the owner's own look, which is kept and shown, and AC.4.1 stays not verified;
  the report says the requirement needs a second person and how to record their review.
- **An entry with no answer to the question** (every entry made before this) is treated as the person who asked, and
  `sv review` asks again.

## Where the build differs

- **Only the owner's own entry can count.** A check by hand the AI coding tool wrote, confirmed by the owner, is not a
  person's review of the code, as AC.4.1 says ("the AI agent itself does not count as the human reviewer"), and the
  confirmation's seal does not cover the entry's own fields; so for AC.4.1 it credits nothing, and the report says
  why. `sv review` asks its question for the owner's entry, where the answer is sealed with the rest.
- **The answer is a field of the entry,** `reviewer = "someone-else"` or `"the-requester"`, written by `sv review` before
  the entries are listed, shown in the list, and sealed with the entry when the owner records it. The seal covers it
  only when it is there, so every seal made before it still holds; the AI coding tool changing it afterwards breaks the
  seal. `sv review` asks again whenever the entry is not yet recorded, whatever the field says.
- **What the report says:** a gap naming AC.4.1, saying what was recorded (the requester's review, no answer, or the AI
  tool's check), that the requirement asks for a second person, and how to record theirs. The check stays as it was
  recorded.
- **Held by** the tests named above. With AC.4.1 credited whoever reviewed it, or the answer left out of the seal,
  they fail.
