# ADR-047: V3.4.3 is credited only for a Content-Security-Policy with the directives it names

**Status:** accepted, 7 October 2026, in the pull request that builds it; proposed the same day with the backlog claim
(#886). The decision is the owner's, of 7 October 2026 ("The check should look for them").

**Governs:** `crates/sv-check/src/probes.rs` (the list of missing headers both header checks read). A pull request that
changes what V3.4.3 is credited for changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

V3.4.3 (ASVS 5.0, level 2) asks for a Content-Security-Policy that "as a minimum, a global policy must be used which
includes the directives object-src 'none' and base-uri 'none' and defines either an allowlist or uses nonces or
hashes". `probe.security-headers` (the pages a stranger sees) and `probe.private-page-headers` (the pages a signed-in
person sees) credited V3.4.3 for any Content-Security-Policy header at all, `frame-ancestors 'none'` alone included.
The prompt-library review of 7 October 2026 found it.

## Decision

- **A page's policy counts toward V3.4.3 only when it has all three:** `object-src 'none'` (or no `object-src` and
  `default-src 'none'`, which a browser reads the same way); `base-uri 'none'`, which nothing else stands in for; and
  a `default-src` or a `script-src`, the allowlist the requirement asks for.
- **A policy short of any is named in the header check's finding**, as a missing header is, with what it lacks. The
  four headers are judged together, as before, so V3.4.4, V3.4.5, and V3.4.6 are held back with it.

## Alternatives considered

- **A rule of its own for V3.4.3.** Clearer in the report, but the header checks credit their four requirements
  together, and splitting them is a larger change than the decision asked for.
- **Leaving the citation and saying "partly".** `sv` has no "partly"; a credit is a claim the requirement is met.

## Later, 12 October 2026: V3.4.6 is met by `frame-ancestors` only

The list of missing headers counted framing as refused when either `X-Frame-Options` said DENY or SAMEORIGIN or the
Content-Security-Policy had `frame-ancestors`. V3.4.6 asks for the policy's `frame-ancestors` and says
`X-Frame-Options` "is obsolete and may not be relied upon". Now only `frame-ancestors` counts; a page that relies on
`X-Frame-Options` alone is short of V3.4.6, and the finding says so as obsolete rather than missing, since browsers
still honor it. `examples/notes-with-users`, which relied on it, now sends `frame-ancestors 'none'` too. Backlog 0264.

## Later, 14 October 2026: a header or cookie finding names only what it found failing (backlog 0432)

`probe.security-headers` and `probe.private-page-headers` cite V3.4.3 to V3.4.6, and `probe.cookie-attributes` and
`probe.session-cookie-attributes` cite V3.3.2 and V3.3.4, and each finding named all of its rule's requirements
whatever was missing. A page whose only lapse was `Referrer-Policy` marked V3.4.3, V3.4.4, and V3.4.6 *needs attention*
for headers it had, and a cookie with `HttpOnly` and no `SameSite` marked V3.3.4 failing. Each gap the check lists is
now paired with the requirement it falls short of (the policy's minimum V3.4.3, `X-Content-Type-Options` V3.4.4,
`Referrer-Policy` V3.4.5, `frame-ancestors` V3.4.6; `HttpOnly` V3.3.4, `SameSite` V3.3.2), and the finding names only
those, still one finding per rule with the same evidence and words. A clean answer still credits the rule's whole list.
