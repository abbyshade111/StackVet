# ADR-140: The bill of materials leaves out lockfiles in test code and in folders named as not the app

**Status:** proposed, 23 October 2026, with the claim for backlog 0656, at the owner's answer of that day to backlog 0647's choices, asked how StackVet should tell a real fault from the
false alarms its path rule raised on its own code: "SBOM skips test lockfiles". It becomes
accepted in the pull request that builds it.

**Governs:** while proposed, the claim it is made with, `docs/backlog/0656-the-bill-of-materials-leaves-out-lockfiles-in-test-folders.md`; the pull request that builds it
replaces that with the files it changes. A pull request that changes which lockfiles and manifests the bill of materials reads changes this record too,
or says in its description why it does not (`docs/adr/README.md`).

## Context

The bill of materials reads every lockfile and manifest in the app's folder (ADR-037 for Python). StackVet's report on
itself said its list was not complete (`sbom.incomplete`) because it read the sample lockfiles under
`crates/sv-scan/tests/fixtures` as what StackVet ships. A test fixture's lockfile is not what the app installs.

## Decision

- **Lockfiles and manifests in test code** (ADR-139's reading) **and in folders named as not the app**
  (`[repository] not-the-app`) are left out of the bill of materials.
- **It says so:** what the bill of materials says it read names how many were left out and why, as it already names
  what it could not read.
- **A lockfile left out never makes the list complete on its own account,** and an app whose only lockfile is in such
  a folder is said to have none read.
