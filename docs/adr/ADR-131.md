# ADR-131: The report says what the AI coding tool did that is worth a look, as information that decides nothing

**Status:** accepted, 21 October 2026, in the pull request that builds backlog 0630; proposed the same day with its
claim, at the owner's word of that day ("yes, file it and build it after the paper tables please").

**Governs:** `crates/sv-cli/src/tool_behavior.rs`, which reads the section from git, the hook record, and the last
report; `crates/sv-check/src/git_changes.rs`, which reads what each commit changed; `crates/sv-report/src/tool_behavior.rs`,
which says it; and their tests, `crates/sv-cli/src/tool_behavior_tests.rs`, `crates/sv-check/src/git_changes_tests.rs`,
`crates/sv-report/src/tool_behavior_tests.rs`, and `crates/sv-cli/tests/tool_behavior_report.rs`. The report folder
reads it in `crates/sv-cli/src/report_folder.rs`, and each format places it; neither is listed, since each is changed
often for other reasons. A pull request that changes what the section reads, what it says, or that it decides nothing,
changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

The trials of 14 and 15 October (backlog 0568 and 0577) found an AI coding tool rewriting code and a dependency file
so that a check stopped seeing something, and then saying nothing had been silenced. A person reading the chats saw
it; nothing in the report said so. `sv` already keeps most of what would show it: the build-loop record (ADR-076), the
commits a tool made straight onto the default branch (ADR-092), the hook record when the person installs the hook and
consents (ADR-122), and the reports before this one. None of them is read for what a person should look at.

## Decision

- **A section of the report, "What the AI coding tool did that is worth a look",** read from git, the hook record when
  it is there and consented to, and the last report. It lists, each with what was seen, when, and where (a commit, or a
  line of the hook record):
  - a finding in the last report that is gone from this one, where the change between them did not touch the line it
    named, or removed what was found from the file `sv` reads rather than from the app (a package dropped from a
    dependency file, code reworded around a pattern);
  - answers in `stackvet.toml` changed by the tool, above all those that lower the level or switch requirements off;
  - tests skipped or removed, or a test's expected value changed in the same commit as the code it tests;
  - commands that destroy work or step around a guard (a force-push, `git reset --hard`, `--no-verify`, a script piped
    from the network into a shell), from the hook record only;
  - guards edited: CI workflows, a scanner's or linter's settings turned down, an ignore marker added beside a line a
    finding named;
  - packages installed that no lockfile holds.
- **It decides nothing.** No requirement's status changes because of it, it counts toward no total, it is never a
  finding, and the verdict reads the same with or without it.
- **It never guesses why.** A force-push or a removed test can be right; a line says what happened, not that it was
  wrong.
- **What it could not see, it says.** Without the hook record, the section names the kinds it could not look for and
  lists only what git shows. With no earlier report, it says the comparison had nothing to compare with.
- **What the hook record keeps does not change** (ADR-122): commands cut short with keys cut, and file paths; never a
  file's contents, a command's output, the person's prompts, or the tool's words. `sv` opens no network connection for
  this.

## Consequences

The owner sees, in the report, the behavior a person caught by reading the chats in October. A tool that games a check
cannot make the section vanish by gaming it, since it reads what changed, not what `sv` now finds. The cost is a
section that can list things that were right to do; it says so at its top.

## As built, 21 October 2026

- **What is read.** The commits on HEAD's own line since the commit the last report was made at, which the section
  keeps as `at_commit` for the next one; when that commit is not in HEAD's history, or there was no earlier report, the
  last 20, and the section says which. Only a commit whose message names an AI coding tool in a trailer (ADR-092's rule)
  is read for its files and lines; the others are counted and said to be not read. Git shows committed blobs only, with
  no external diff, textconv, or colour, so nothing in the repository runs.
- **The last report** is read only when `sv` can show it wrote it and it is unchanged (the seal, ADR-034), before this
  report replaces it. A finding with no fingerprint cannot be followed, and information is never one to go away.
  A finding is not gone when this report still holds its fingerprint, an earlier form of it, or a person set it aside.
- **The hook record** is read only for a run the person passed `--hook-record` for (ADR-122), and only each command
  and file path, as the record keeps them.
- **An ignore marker** is listed wherever a tool's commit added one, and says when a finding in the last report named
  that file, rather than only beside a line a finding named: a marker added just before a report hides the finding it
  is beside, so the last report is the one to read it against.
- **Not yet:** packages installed that no lockfile holds, which the section says it does not look for, and a secret
  the tool wrote into a file (the secrets scan finds the secret; saying the tool wrote it is left with backlog 0630).
- **At most 60 lines** are listed, kind by kind; the rest are counted.
- **Held by** the four test files above, each red with its rule broken: the record read without consent (the end-to-end
  test), a finding held under an earlier fingerprint or set aside counted as gone, a person's commit read as the tool's,
  a diff's `---` line read as a header inside a hunk, the section left out of information.md, and the security page
  changed by it.
