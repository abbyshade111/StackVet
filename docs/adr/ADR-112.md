# ADR-112: A security contact that is a placeholder is a finding of its own, and cites no requirement

**Status:** accepted, 14 October 2026, in the pull request that builds it (backlog 0405). Written by session
documentation, from the owner's trial in Antigravity of 13 October 2026.

**Governs:** `crates/sv-check/src/security_contact.rs`, which runs the check this record adds,
config.security-contact-placeholder, from the configuration checks in `crates/sv-check/src/config.rs`. A pull request
that changes what it says about this changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

In the owner's trial of 13 October 2026, the AI coding tool wrote the app's `SECURITY.md` early in the build. It gave
`security@example.com` as the contact and promised "We acknowledge reports within 48 hours", a commitment the owner
never made. `example.com` is kept for examples (RFC 2606) and takes no mail, so a real report would go nowhere.
`config.security-contact` credited the file for being there, and nothing read what it said.

No requirement speaks to a disclosure contact. ASVS 5.0, AISVS 1.0 and its Appendix C, and the Secure by Design
checklist were searched for one on 14 October 2026 and none asks for a way to report a vulnerability, as ADR-049 found
before; `config.security-contact` cites none for that reason.

## Decision

- **A new check, config.security-contact-placeholder,** reads every file `config.security-contact` finds (a
  `SECURITY` file at the root, in `.github/` or `docs/`, or a `security.txt` where a site serves it) line by line.
- **A placeholder is:** an email address at `example.com`, `example.org`, or `example.net` or a name under them;
  under the names RFC 2606 keeps for tests and examples (`.example`, `.test`, `.invalid`); at `localhost`; or at a
  domain beginning `your` (`yourdomain.com`). A web address on a `Contact:` line, as security.txt gives one, is read the
  same way; elsewhere in a `SECURITY.md` an `example.com` address may be an example of something else and is left
  alone. Stand-ins left to be filled in count too: `you@`, `your-email` and its spellings, `changeme`, and `<your ...>`
  or `[your ...]`.
- **A low finding at the first such line,** saying how many more there are, with the reason the name reaches nobody.
  Its fix also asks the owner to check any reply time the file promises, since an AI tool may have written it.
- **It cites no requirement and credits none.** A clean read is a pass with no requirement, as
  `config.security-contact`'s is: evidence about no requirement in particular, which the reports show rather than
  hide. With no security file, the check is not assessed and says why; `config.security-contact` is the finding then.
  A file that cannot be read as text makes the check not assessed, naming it.

## Alternatives considered

- **Folding it into config.security-contact,** failing that check when every contact is a placeholder. Rejected: the
  two say different things (there is no file; the file's contact goes nowhere), and a person fixing one should see
  which.
- **Reading every web address in a `SECURITY.md`.** Rejected: a policy may show an example request against
  `example.com`, and that is not its contact.
- **Checking that a real address takes mail.** Rejected: `sv` opens no network connection of its own for what it reads
  (`docs/ARCHITECTURE.md`, "The fence").
