# ADR-132: stackvet.dev is built from the repository first, and where it is hosted is chosen after

**Status:** accepted, 22 October 2026, in the pull request that builds the site; proposed the same day with the
claim for backlog 0376, at the owner's answer of that day, asked in a session where stackvet.dev should be hosted:
"Build first then do some research and provide up to 5 options, a mix of free and low cost, with the pros and cons
and your recommendation".

**Governs:** `tools/website.py`, `crates/sv-cli/tests/website.rs`, `.github/workflows/site.yml`,
`deploy/stackvet.dev/wrangler.jsonc`, `crates/sv-cli/tests/site_workflow.rs`, `crates/sv-cli/tests/site_environment.rs`, `docs/website/how-it-works-page.md`,
`docs/website/build-walkthrough-page.md` (with the screens in the folder beside it), `docs/website/check-a-project-page.md`, `docs/website/configvet-page.md`,
`docs/website/self-assessment/README.md`, and the repository's own `stackvet.toml` (what StackVet's report on itself is held to); and, added by the ninth weekly review (23 November 2026), `.github/workflows/site-weekly.yml`, `crates/sv-cli/tests/site_weekly.rs`, `docs/website/agentvet-page.md`. A pull request that changes what the
site is built from, where it is written, or that nothing of it is published without the owner's word, changes this
record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

The home page's words and look were settled on 12 October 2026 (`docs/website/home-page.md`, backlog 0224), and the
framework pages are written by `tools/framework_pages.py` into `exports/site/` (ADR-129). Every condition 0376 set for
building is met; going live still waits for the walk-through (backlog 0373) and the owner's word. Where the site is
hosted, and how stackvet.dev and stackvet.app point at it, are the owner's: hosting may cost money.

## Decision

- **Built first, by a script in the repository,** with no dependency beyond Python's own library: the home page, the
  credits page, How StackVet works, StackVet checks itself, and the reports page, beside the framework pages, into
  `exports/site/`, which git ignores, as `tools/framework_pages.py` writes.
- **Read, never copied,** as ADR-129 holds the framework pages: the words from `docs/website/home-page.md` and
  `docs/website/reports-page.md`, the coverage numbers from `docs/COVERAGE.md`, the credits from the licenses the
  repository records, and the self-assessment and its bill of materials from where they are kept.
- **Self-contained:** no script, style sheet, font, or image is fetched from anywhere; the type falls back to the
  system's when Atkinson Hyperlegible is not installed.
- **Hosted on Cloudflare,** the owner's choice of 22 October 2026 from the five options brought after the build
  (Cloudflare, GitHub Pages, Netlify, Codeberg Pages, and Bunny.net): "Let's go with Cloudflare, the domains are
  registered via Cloudflare already". It serves static files free and without limit, and it is the one free choice
  of the five that sends response headers a site sets, which a security tool's own site should; both addresses' DNS
  is already there, so stackvet.app can redirect to stackvet.dev by a rule on its zone. The build writes `_headers`:
  a content security policy that allows only the scripts the build wrote, by their hashes, and loads nothing from
  elsewhere, with the headers against framing, type guessing, and the referrer.
- **Nothing is published** by building it. Hosting is chosen by the owner from up to five options, free and low cost,
  each with its pros and cons and a recommendation, researched after the site is built and recorded here when chosen.

## Later, 22 November 2026: the pages say `Cache-Control: no-transform` (backlog 0740)

The review of stackvet.dev's Cloudflare settings that day found Cloudflare adding a bot-detection script of its own to
every page, its JavaScript detections: an inline `<script>` and `/cdn-cgi/challenge-platform/scripts/precursor/main.js`.
The site's content security policy allows only the scripts the build wrote, by their hashes, so browsers blocked it:
it failed in every visitor's browser, gave Cloudflare nothing, and the pages served were not the pages built.
Cloudflare's documentation says JavaScript detections "cannot be disabled" for Bot Fight Mode customers; the zone, on the
Free plan with Bot Fight Mode off, still had it. It also says the script is not added to a response that carries
`Cache-Control: no-transform`. So `_headers` now gives every path `Cache-Control: public, max-age=0, must-revalidate,
no-transform`: what the site was served with until then, so a deploy still shows at once, and `no-transform`.

Measured before, for the owner to weigh after the deploy: every file was sent brotli-compressed, the home page 7,487
bytes on the wire for 21,703, and the bill of materials 6,282 for 88,905. If `no-transform` stops Cloudflare
compressing, the owner chooses whether the larger transfers are worth pages served exactly as built.

Measured after the deploy, 22 November 2026: no page carried Cloudflare's script, and every page sent the new
`Cache-Control`; but Cloudflare stopped compressing everything, the home page 21,061 bytes on the wire (7,487 before),
`/configvet` 24,139 (8,013), and the bill of materials 88,905 (6,282). The owner chose, asked with a recommendation
("Pages only"): `no-transform` stays on the pages, where the script was added, and every other kind of file the build
writes gets a rule of its own that drops it (`! Cache-Control`, then the plain value again, since Cloudflare joins a
header set twice), so Cloudflare compresses it as before. The rules are written for each kind of file found, so a new
kind is never missed.

Checked after the deploy of the pages-only rules, 22 November 2026: no page carries Cloudflare's script, and pages send
`no-transform`; the other files are compressed again, the bill of materials 6,283 bytes on the wire (6,282 before
0740), and `favicon.svg` and the example report's `report.json` brotli-compressed too. Backlog 0740 is done.
