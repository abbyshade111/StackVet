# ADR-129: stackvet.dev has a page for each framework, built from the data the checks keep, and never copied

**Status:** accepted, 20 October 2026, in the pull request that builds it; proposed the same day with the claim for
backlog 0619.
The owner's choice of 20 October 2026, asked in a session: "Generator + local preview", over folding the pages into
the site's build first (backlog 0376) or mocking them up on a canvas first.

**Governs:** `tools/framework_pages.py`, `crates/sv-cli/tests/framework_pages.rs`, and `docs/website/home-page.md`
(the words and the look the pages follow). A pull request that changes these changes this record too, or says in
its description why it does not (`docs/adr/README.md`).

## Context

The site's words and look are settled (backlog 0224, direction C, `docs/website/home-page.md`), and its build is
open (backlog 0376) with no page for the frameworks. Its section "What it checks" gives three counts, read from
`docs/COVERAGE.md` when the site is built. A person deciding whether StackVet fits their app wants the next step
down: for each requirement, what it asks in plain words and what StackVet does about it, which is a check that can
mark it checked, one that can only find it failing, a question only the person can answer, or nothing.

All of that is already kept, where the checks keep it: the standards in `data/frameworks/`, the plain words in
`data/plain-requirements.json`, the classification in `tools/coverage.py` (which writes `docs/REQUIREMENTS.md` and
`docs/COVERAGE.md`), the person's questions in `data/design-questions.json`, `data/security-notes.json`,
`data/human-checks.json`, and `data/design-decisions.json`, and when a requirement applies in
`data/knowledge/applicability.json` and `data/applicability-v2.json`. On 20 October 2026 the same facts were put
into three spreadsheets for the owner, built by a script outside the repository.

## Decision

- **A script in `tools/` writes the pages, from the data and nothing else.** One page each for ASVS 5.0, AISVS 1.0
  with its Appendix C, and the Secure by Design checklist 0.5.0: every requirement, by family and level, with the
  standard's words, StackVet's plain words, its coverage, the checks that speak to it and what each needs to run,
  what a person is asked and how, and when it applies. Each requirement has an anchor of its own, so a report or
  another page can link to it.
- **The classification is `tools/coverage.py`'s,** called, not written again, so a page cannot say a check
  covers more than `docs/REQUIREMENTS.md` says; a test holds the pages' counts to `docs/COVERAGE.md`'s.
- **The pages say what a result is not,** as the report does: a clean check is one automated check satisfied, not
  proof the requirement is met, and an answer a person gives counts only once `sv review` records it.
- **A local preview first.** The script writes into a folder given with `--out` (by default `exports/site/`, which
  git ignores) and fetches nothing. Where the site is hosted is still the owner's to decide, and asked first, since
  it may cost money (backlog 0376); nothing is published until the owner says so.
- **The look is direction C,** in the palette and type `docs/website/home-page.md` sets, at phone width first.

## Consequences

The site's framework pages are a build step, like its counts: they change when a check changes, and a page that
disagrees with the code is a failing test, not a correction someone has to remember. The pages carry the standards'
own words under their license (CC BY-SA 4.0), with the attribution each standard asks for.

## Where the build differs

- **The coverage words are the site's,** over `tools/coverage.py`'s four kinds: "StackVet can confirm or fail it"
  (can be checked), "StackVet can only show it missing" (can only be found failing), "A check helps; a person
  decides", and "Not checked by StackVet", the phrasing `docs/website/home-page.md` already uses. A Secure by Design
  control is "A check helps; a person decides" or "A person decides", and its level is said to be StackVet's.
- **A level filter,** a few lines of script in the page, shows one level at a time; without it every level is shown.
- **Held by `crates/sv-cli/tests/framework_pages.rs`:** every requirement in `data/frameworks/` has an entry on its
  page; each page's counts equal `docs/COVERAGE.md`'s summary; no page fetches a script, style sheet, font, image, or
  frame, and the only links out are to the standards' sources; and the generator leaves a folder it did not make, and
  any folder in the repository outside `exports/`, as they are. Broken on purpose three ways before this entry was
  written: a requirement left out, a check that only shows a requirement missing counted as one that can confirm it,
  and a font fetched from the web; each failed that test.
