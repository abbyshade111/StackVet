# ADR-134: A seed may print numbered values, and each sign-up takes the next one unused

**Status:** proposed, 23 October 2026, with the claim for backlog 0637, at the owner's answer of that day, asked in a
session how StackVet should handle an invite-only app whose codes work once: "Numbered values". It becomes accepted in
the pull request that builds it.

**Governs:** while proposed, the claim it is made with, `docs/backlog/0637-sign-up-checks-fill-one-seed-value-into-every-account-they.md`; the pull request that builds it replaces that with the
files it changes. A pull request that changes what a seed may print or how `{seed:NAME}` is filled changes this record
too, or says in its description why it does not (`docs/adr/README.md`).

## Context

ADR-124 lets a manifest cite a value the seed printed as `{seed:NAME}`, one value per name. `sv report --run` makes
several accounts through the sign-up form, each with that one value. In the owner's Cursor build of 22 October 2026 the
app's invites worked once, so the first sign-up used the seed's invite up and the rest were refused, and six checks did
not run; the report guessed the sign-up needed "a value stackvet.toml does not carry".

## Decision

- **A seed may print numbered values,** `INVITE_1=…`, `INVITE_2=…`, and so on, beside or instead of `INVITE=…`.
- **`{seed:INVITE}` takes the next numbered value not yet used** for each sign-up, in order, and `INVITE` itself when
  there are no numbered ones, as now. A value is used once.
- **When the seed printed too few,** the sign-ups past them go without, and the report says which checks did not run
  for want of a value, and that the seed can print more.
- **When sign-ups after the first are refused with the same value,** the report says the value likely works once, and
  how to print numbered ones, rather than guessing at a missing field.
- The manifest still never holds the values (ADR-124), and nothing is run that was not run before.
