# ADR-103: A record can govern a named part of a large file, and the "Decision records" check asks only when that part changes

**Status:** accepted, 12 October 2026, in the pull request that builds it. Proposed the same day with the claim for backlog 0268. The owner chose it on 12 October 2026 ("yes, please
claim both as backlog items and fix as you recommend") after the third weekly review found thirteen records with a decision
in a file no record governs. The build follows the plan; where it adds to it is under "Where the build differs".

**Governs:** `tools/adr_check.py`, `crates/sv-cli/tests/decision_records.rs`. A pull request that changes these changes this
record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

A record's **Governs:** list names files, and the check asks about a pull request that touches one. The owner decided on
6 October that the large shared files (`crates/sv-check/src/ai.rs`, `crates/sv-check/src/signed_in/mod.rs`, `rules.rs`,
`crates/sv-cli/src/assemble.rs`, `main.rs`, `lib.rs`, and others) stay ungoverned, since a whole-file pattern makes nearly
every pull request owe a line. The weekly review is then the only thing that notices a change undoing a decision there; on
12 October it found thirteen records affected.

## Decision

- **A pattern may be `path::NAME`.** It matches when the pull request's diff adds or removes a line that contains NAME as a
  whole word (letters, digits and underscores on either side do not count). A change to another part of the file owes
  nothing. A pattern without `::` means what it did.
- **NAME is a thing that carries the decision:** a constant, a table, a function, or a field. It is not a phrase.
- **The references test fails when NAME is no longer in its file,** as it already fails for a pattern that matches nothing.
- **Nothing else about the check changes:** the same "ADR-0NN: unchanged, because ..." line, the same ten characters.

## Alternatives considered

- **Govern the whole files.** Nearly every pull request would owe a line, and the lines would say nothing (backlog 0267 is
  the same problem in the index).
- **Split each decision into its own file.** Cleaner, and a large refactor of code that works; it can still be done one
  decision at a time and then the whole-file pattern is enough.
- **Leave it to the weekly review.** It found thirteen gaps in a week, a week after the change that opened them.

## Consequences

- A rename of NAME stops the check asking, until the references test fails; the test is the guard, and it must be
  run on a rename.
- The check reads a pull request's diff, not only its list of files. It still opens no network connection.
- A name that is too common (a word that appears on most lines) asks too often. A record's author picks the name.

## Where the build differs

- **The first names are in five records:** ADR-021 and ADR-053 (`RESTS_ON_A_REFUSAL`), ADR-064 (`HANG_HOLD`), ADR-067
  (`STATIC_SESSION`) and ADR-088 (`KILL_SWITCH`, `kill_switch`), each with a "Later" entry. The other records that put a
  decision in a large shared file name it as they are next touched; the weekly review lists the ones that do not.
- **The Rust test reads the end of a list as the Python does,** however the standing sentence is wrapped (backlog 0267), so
  the two stay in step; a name that is in no file the path matches fails there.
- **With no changed lines to read, the check asks.** `owed(...)` given none treats `path::NAME` as the whole file; `main`
  always gives them when any record uses the form.

## Tested

`python3 tools/adr_check.py --self-test` (a change elsewhere in the file owes nothing; the name fires it; a longer name,
another file, and a name in a deleted file; a real git repository for the changed lines), and in
`crates/sv-cli/tests/decision_records.rs`: `a_record_that_governs_a_named_part_fails_when_the_name_is_gone`,
`a_name_is_found_only_as_a_whole_word`, and `the_standing_sentence_ends_the_list_however_it_is_wrapped`. Each was broken
on purpose and put back: the name ignored, no word boundary, no lines meaning silence, a deleted file's lines lost, the
header never ending (Python); the name never checked, no boundary, the list never ending (Rust). Each went red on the
case written for it.
