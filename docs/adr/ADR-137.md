# ADR-137: A check that reads code for a setting does not read it in a comment, or in a file of another programming language

**Status:** accepted, 23 October 2026, in the pull request that builds it; proposed the same day with the claim for
backlog 0645, from the triage of StackVet's findings on its own repository (backlog 0633), which asks that a rule found
wrong is fixed, with a test that it still fires where it should.

**Governs:** `crates/sv-check/src/cert_checks.rs::SWITCHES`, `crates/sv-check/src/cert_checks.rs::PROGRAMMING`,
`crates/sv-check/src/cert_checks.rs::commented`, `crates/sv-check/src/weak_keys.rs::weak_keys_in`, and their tests
(`crates/sv-check/src/cert_checks_language_tests.rs`, `crates/sv-check/src/weak_keys/comment_tests.rs`). A pull request
that changes what the weak-key check or the certificate check reads changes this record too, or says in its
description why it does not (`docs/adr/README.md`).

## Context

Two checks of StackVet's own match text. The weak-key check (V11.6.1, `crates/sv-check/src/weak_keys.rs`) matches a
key made too weak, and it also reads comments. The certificate check (`crates/sv-check/src/cert_checks.rs`) matches a
setting that switches certificate checking off, and it already skips comment lines; but it reads Python's and Node's
switch-offs in a file of any language. In StackVet's report on itself, all 9 weak-key findings were the comments that
describe the check's own patterns, and both certificate findings were Rust strings naming the Python and Node
settings. A comment makes no key, and a Python statement in a Rust string does nothing.

## Decision

- **The weak-key check skips comment lines,** as the certificate check does.
- **A switch-off written for one language counts in files of that language,** and in files of no programming language
  of their own, where a shell, a Dockerfile, a notebook, or a configuration file can run it (`python -c "..."`). Python's
  `ssl._create_default_https_context` is read in Python; Node's `https.globalAgent.options.rejectUnauthorized` is read in
  JavaScript and TypeScript; Deno's `--unsafely-ignore-certificate-errors` is a command-line flag and is read
  everywhere, as now.
- **Finding nothing still credits nothing,** as both checks already say.
- Held by tests of what must still fire: a key made in code, a switch-off in a `.py` file and in a shell script's
  `python -c`.

## Where the build differs

- **"A file of another programming language"** is one whose language `sv` names as one of its own: JavaScript,
  TypeScript, Python, Java, Kotlin, Go, Rust, Ruby, PHP, C#, C, Dart, Swift, C++, or Objective-C. Shell scripts, pages,
  notebooks, templates, and every file `sv` names no language for (a Dockerfile, YAML, TOML, `.env`) are read for
  every switch, since they can run another language's line. Node's switch counts in JavaScript and TypeScript; a page's
  script is read as such, since pages are not on that list.
- **A comment line** is one that starts, after spaces, with `#`, `//`, `/*`, `*`, `;`, `<!--`, or `REM`, as the
  certificate check already read it. For the weak-key check it is the line the match starts on, so a key made in code
  with a comment after it on the same line is still found.
- **Held by** the two test files: with every switch read in every language, the language test fails; with comments
  read, the comment test fails. Each also holds what must still be found.

## Later, 23 October 2026: the weak-key check reads test code

At the owner's answer of that day to backlog 0647's choices ("Weak-key check labels, not skips"), backlog 0655: the
weak-key check no longer skips test files. A weak key made in test code is found, and its finding is marked as test
code where the report marks every finding, so it is listed apart and still counts (ADR-023), as the code rules' findings
are. Building backlog 0654 showed why: once the check knew Rust's test modules, it skipped them too, and StackVet's own
V11.6.1 went from "needs attention" to "not verified" because the six weak keys in a test of its own were no longer
seen. Held by `crates/sv-check/src/weak_keys/test_code_tests.rs`: with test code skipped again, it fails.
