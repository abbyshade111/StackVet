# ADR-122: The hook record, kept by a hook the person installs, read only with their consent

**Status:** proposed, 15 October 2026, by wording, before building backlog 0566 (the owner's go of 14 October: "build
it whenever the board has room"). Backlog 0565 is built on it after it, by the owner's answer of 15 October: Claude
Code's documentation calls the entry format of its own transcript internal and liable to change between releases, so
`sv` reads what a documented hook hands over instead. Accepted in the pull request that builds 0566.

**Governs:** `crates/sv-cli/src/connect.rs`, which prints the hook, and the files the building pull request adds to
write and read the record, which it names here. A pull request that changes what the hook records, where, or what a
report says of it changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

Every view `sv` has of an app's build goes through something the AI coding tool controls: its calls to `sv`, its
files, its start command, its own account of what it did. In the three-tool trial (`docs/research/SETUP-PROMPT-TRIALS-2026-10-14.md`)
a reviewer had to read each tool's transcript against the files to find "the tests pass" with no test run. A hook
the tool runs after each of its actions is the one view from outside the tool's own account, and Claude Code documents
what a hook is handed (its hooks page, "Common input fields", `PostToolUse`, and `Stop`).

## Decision (proposed)

1. **What `sv` asks to be installed, and how.** `sv connect claude --hook` prints a `hooks` block for Claude Code's
   settings; the person adds it. `sv` never writes it into the tool's settings. The hook runs on `PostToolUse` for the
   tools that run a command or write a file (`Bash`, `Edit`, `Write`, `MultiEdit`, `NotebookEdit`) and on `Stop`, and
   each runs `sv hook-record`, which reads the hook's input on standard input. Only Claude Code for now: its hook
   input is documented; another tool is told "not yet". The hook runs the `sv` installed on the computer; a person
   with only Docker is told it is not offered for them yet.
2. **What a line holds.** The time by `sv`'s clock, the hook's event and tool, the session's id, and either the
   command, cut short and with any key cut as the secrets scan cuts one (its first four characters and its length), or
   the path of the file written, relative to the app. Never a file's contents, a command's output, the person's
   prompts, or the tool's words: a `Stop` line says only that a turn ended. 0565 adds what it needs under its own
   entry here, and asks first if that is more.
3. **Where it is kept.** Outside the app's folder, in `sv`'s own state folder (`$XDG_STATE_HOME/stackvet/hook-records/`,
   or `~/.local/state/stackvet/hook-records/`), one file per app named by a hash of the app folder's path, readable
   only by the person: a tool clearing the app's folder does not take it, and it is never committed with the app.
4. **Chained, as the build-loop record is** (ADR-076): each line's chain is a SHA-256 over the line before's chain and
   its own text.
5. **Read only with the person's consent, for that run.** `sv report --hook-record` reads it; nothing reads it
   otherwise, and the MCP server never does, since the AI coding tool cannot consent for the person. The report has a
   section of its own, apart from every count, that credits nothing: how many commands and file writes the hook saw
   and over what time, the test commands among them and when the last ran, and whether the chain holds. The chain's
   tip (its line count and last chain) goes into `report.json`, under the report's seal; when the last sealed report's
   tip is no longer on the chain, the report says the record was rewritten or cut since that report.
6. **What it says it is.** A record a hook kept on this computer. The AI coding tool runs as the person and could
   change it; the chain and the sealed tip show a change made after an earlier report, not one made before it. A
   switched-off hook shows as a record whose last line is older than the work.

## Alternatives considered

- **The tool's own transcript.** Claude Code's documentation says its entry format is internal and changes between
  releases; the owner chose the hook (0565).
- **`sv` writing the hook into the tool's settings.** Simpler for the person, but `sv` writes nothing into the AI
  coding tool's settings, and a person who pastes the block sees what it runs.
- **The record in the app's folder,** as the build-loop record is. An AI tool clearing the folder, or a commit, would
  take or publish it; it records the person's commands, so it is kept as `sv history` is, outside every app.
