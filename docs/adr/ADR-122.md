# ADR-122: The hook record, kept by a hook the person installs, read only with their consent

**Status:** accepted, 15 October 2026. Proposed by wording before building backlog 0566 (the owner's go of 14 October:
"build it whenever the board has room"), and built as proposed but for what "Where the build differs" says. Backlog
0565 is built on it after it, by the owner's answer of 15 October: Claude Code's documentation calls the entry format
of its own transcript internal and liable to change between releases, so `sv` reads what a documented hook hands over
instead.

**Governs:** `crates/sv-cli/src/connect.rs`, which prints the hook; `crates/sv-cli/src/hook_record.rs`, which writes
the record and reads it back; `crates/sv-report/src/hook.rs`, which says what it held in the reports; and their tests,
`crates/sv-cli/src/hook_record_tests.rs`, `crates/sv-cli/src/hook_record_claims_tests.rs`,
`crates/sv-cli/tests/hook_record_command.rs`, `crates/sv-report/src/hook_tests.rs`, and
`crates/sv-report/src/hook_claims_tests.rs`. A pull request that changes what the hook records, where, or what a report says
of it changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

Every view `sv` has of an app's build goes through something the AI coding tool controls: its calls to `sv`, its
files, its start command, its own account of what it did. In the three-tool trial (`docs/research/SETUP-PROMPT-TRIALS-2026-10-14.md`)
a reviewer had to read each tool's transcript against the files to find "the tests pass" with no test run. A hook
the tool runs after each of its actions is the one view from outside the tool's own account, and Claude Code documents
what a hook is handed (its hooks page, "Common input fields", `PostToolUse`, and `Stop`).

## Decision

1. **What `sv` asks to be installed, and how.** `sv connect claude --hook` prints a `hooks` block for Claude Code's
   settings; the person adds it. `sv` never writes it into the tool's settings. The hook runs on `PostToolUse` for the
   tools that run a command or write a file (`Bash`, `Edit`, `Write`, `MultiEdit`, `NotebookEdit`) and on `Stop`, and
   each runs `sv hook-record`, which reads the hook's input on standard input. Only Claude Code for now: its hook
   input is documented; another tool is told "not yet". The hook runs the `sv` installed on the computer; a person
   with only Docker is told it is not offered for them yet.
2. **What a line holds.** The time by `sv`'s clock, the hook's event and tool, the session's id, and either the
   command, cut short and with any key cut as the secrets scan cuts one (its first four characters and its length), or
   the path of the file written, relative to the app. Never a file's contents, a command's output, the person's
   prompts, or the tool's words: a `Stop` line says only that a turn ended. 0565 adds what it needs under its own
   entry here, and asks first if that is more.
3. **Where it is kept.** Outside the app's folder, in `sv`'s own state folder (`$XDG_STATE_HOME/stackvet/hook-records/`,
   or `~/.local/state/stackvet/hook-records/`), one file per app named by a hash of the app folder's path, readable
   only by the person: a tool clearing the app's folder does not take it, and it is never committed with the app.
4. **Chained, as the build-loop record is** (ADR-076): each line's chain is a SHA-256 over the line before's chain and
   its own text.
5. **Read only with the person's consent, for that run.** `sv report --hook-record` reads it; nothing reads it
   otherwise, and the MCP server never does, since the AI coding tool cannot consent for the person. The report has a
   section of its own, apart from every count, that credits nothing: how many commands and file writes the hook saw
   and over what time, the test commands among them and when the last ran, and whether the chain holds. The chain's
   tip (its line count and last chain) goes into `report.json`, under the report's seal; when the last sealed report's
   tip is no longer on the chain, the report says the record was rewritten or cut since that report.
6. **What it says it is.** A record a hook kept on this computer. The AI coding tool runs as the person and could
   change it; the chain and the sealed tip show a change made after an earlier report, not one made before it. A
   switched-off hook shows as a record whose last line is older than the work.

## Alternatives considered

- **The tool's own transcript.** Claude Code's documentation says its entry format is internal and changes between
  releases; the owner chose the hook (0565).
- **`sv` writing the hook into the tool's settings.** Simpler for the person, but `sv` writes nothing into the AI
  coding tool's settings, and a person who pastes the block sees what it runs.
- **The record in the app's folder,** as the build-loop record is. An AI tool clearing the folder, or a commit, would
  take or publish it; it records the person's commands, so it is kept as `sv history` is, outside every app.

## Where the build differs from the proposal

- **The tools and events are the ones Claude Code's hooks page documents.** It lists `Bash`, `PowerShell`, `Write`,
  and `Edit` (not `MultiEdit` or `NotebookEdit`), so the matcher is `^(Bash|PowerShell|Edit|Write)$`. A command that
  exits with an error reaches a hook as `PostToolUseFailure`, not `PostToolUse` (the page's own example is a failed
  `npm test`), so the hook is on both, and a line says which: the report says whether the last test command failed.
- **Two hooks at once.** Claude Code can run several tools together, each running the hook; the record is locked while
  a line is chained and written, so two cannot chain to the same line.
- **Kept small.** A command is cut to 300 characters; the record stops growing at 16 MB and `sv hook-record` says so.
- **A failure never blocks the tool.** `sv hook-record` exits 1 when it cannot write, which Claude Code shows as a hook
  error and carries on; never 2, which would block the tool's action.
- **`sv review` writing the report again does not read the record.** Consent is for the run the person types it for,
  so `--hook-record` is not among the options a report keeps for `sv review` to repeat (backlog 0578).

## Later, 15 October 2026: a turn's end keeps what kind of claim the tool made, never its words (backlog 0565)

0565 was to read the AI coding tool's own transcript for where what it said differs from what it did; the owner chose,
the same day, to build it on this record instead, from `Stop`'s documented `last_assistant_message`. Decision 2 kept
none of the tool's words, and still does: `sv hook-record` reads the message when the hook hands it over, keeps only the
kinds of claim it finds in it (`claims`, today one, `tests-pass`: a sentence naming tests and passing, with no word of
failing, of not passing, or of an intention or condition such as "will" or "once"), and drops the rest. A report read
with `--hook-record` counts the turns that claimed it, and names each one whose own session's record shows otherwise:
no test command had run in that session, the last one failed, or files were written after it. It quotes none of what
the tool said. The claims about security that 0565 also named ("rate limiting added") are backlog 0607: each needs the
requirements it speaks to, read first. Held by `crates/sv-cli/src/hook_record_claims_tests.rs` and
`crates/sv-report/src/hook_claims_tests.rs`.

## Later, 16 October 2026: the claims about security a turn ends with, each beside the report's own verdict (backlog 0607)

Besides the claim that the tests pass, the hook record now keeps eight kinds of claim about security a turn's end may
make, by kind and never in the tool's words (`sv_report::hook::CLAIM_KINDS`): rate limiting or lockout (V2.4.1,
V6.3.1), cross-site scripting (V1.2.1, V3.2.2), forged requests and the anti-forgery token (V3.5.1), how passwords are
stored (V11.4.2), SQL injection (V1.2.4), command injection (V1.2.5), access control (V8.2.1), and secrets kept out of the
code (V13.3.1). Each mapping was read from the requirement's own text. A sentence claims a kind when it names it, says
it is done ("added", "fixed", "hashed", "enabled", "in place"), and says nothing of not, failing, intending, or a
condition, as the tests claim already is.

The report's hook section says, for each kind, how many turns ended with it and what this report shows for each of its
requirements ("V2.4.1, needs attention"), followed by "That is what the code and the checks show, whatever the tool
said." That wording is 0538's: what the code shows, never a word the tool could rewrite to change it. It credits
nothing. The requirement verdicts are the report's own. Held by `crates/sv-cli/src/hook_record_kinds_tests.rs` and
`crates/sv-report/src/hook_kinds_tests.rs`, red with the kinds not read, not counted, or not said.

## Later, 21 October 2026: the record read for what the AI coding tool did that is worth a look (backlog 0630, ADR-131)

`hook_record::done_for` reads each command and file path the record keeps, for the report's section on what the tool
did that is worth a look, only for a run the person passed `--hook-record` for, as `read_for` is. Nothing the hook
writes changes. The section shows a command it lists as the record keeps it, cut short with keys cut, as the hook
section already shows the last test command; never a file's contents, a command's output, the person's prompts, or the
tool's words. Held by `crates/sv-cli/tests/tool_behavior_report.rs`, red with the record read without consent.
