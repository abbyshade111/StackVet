0581 (your answer A: sv connect --docker mounts the trusted-keys list and the public key, read-only). Found while building: the seal check reads only the trusted-keys list (allowed_signers); it never reads the public key file, so mounting it changes nothing in what the container counts. Mounting it also has a cost: Docker makes a folder where a mounted file does not yet exist, and the public key file exists only after the first sv review, so on most computers the mount would put a folder at ~/.config/stackvet/review-signing-key.pub, and sv review would then fail to make its key. Either way the container counts the seals and says it cannot tell whether the key has a passphrase. A1 (recommended): mount the trusted-keys list only, which the setup already makes empty beforehand. A2: mount both as answered, and the setup makes both files first, the public key as an empty file. Also part of either: sv connect runs inside the container and cannot see your home folder, so it gains an option naming the key folder (--keys ~/.config/stackvet), which the setup prompt passes.
